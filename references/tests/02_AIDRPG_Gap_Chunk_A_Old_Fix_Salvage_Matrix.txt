AIDRPG Gap Chunk A — Old Fix Salvage Matrix

0. Document status

Document name: AIDRPG Gap Chunk A — Old Fix Salvage Matrix
Purpose: Map every known old AIDRPG repair/fix system into the new architecture so no tested safeguard is accidentally lost.
Status: Pre-code blocker.
Applies after: AIDRPG Gap Closure Addendum v1.
Applies before: Runtime and Hook Contract Spec, Story Card API Adapter Spec, Parser Rulebook, and Script v0.1 coding.
This document does not contain final script code.

This matrix answers:

* what each old fix/system was trying to protect
* what went wrong with the old approach
* whether the idea should be kept, rewritten, deferred, discarded, or kept only as a test
* which new module owns the repaired version
* whether it belongs in MVP or later
* which test proves the old issue will not return

The goal is not to copy old code.

The goal is to preserve every useful safety lesson.

⸻

1. Salvage doctrine

Old AIDRPG/TASIS versions became unstable because useful fixes were added as patches, wrappers, or late repair layers instead of being absorbed into one controlled canon pipeline.

The new doctrine is:

Do not paste old systems back in whole.
Extract the useful rule.
Assign it to one owner module.
Route it through the event/proposal/validation/reducer pipeline.
Add an audit surface.
Add a regression test.

No old fix is considered preserved unless it has:

1. a named issue it prevents
2. a new owner module
3. a validation/non-canon rule
4. a reducer or read-only boundary
5. an audit/debug surface
6. at least one regression test

⸻

2. Decision labels

Each old system receives one of these decisions.

KEEP IN MVP

The concept is required in the first MVP and should be implemented in the new architecture.

REWRITE IN MVP

The old concept is required, but the old implementation style is unsafe. Rebuild it under the new architecture.

DEFER WITH MINI-SPEC

The concept is valid, but it is too advanced for MVP and requires its own mini-spec before implementation.

DISCARD IMPLEMENTATION, KEEP TEST

The old implementation should not be reused, but the bug it exposed must remain a regression test.

DISCARD

The old behavior is obsolete, redundant, or harmful and should not be carried forward.

5. Old Fix Salvage Matrix

5.1 RuntimeGate

Original purpose: Validate hook inputs and fail softly instead of crashing AI Dungeon.

Old problem: Runtime checks existed, but they were layered alongside many systems and could not guarantee the rest of the hook stayed clean.

Decision: REWRITE IN MVP.

New owner: RuntimeHookContract + StateManager + AuditLogger.

MVP or deferred: MVP blocker.

New implementation rule: Every hook validates runtime inputs before touching gameplay logic. On failure, return safe text, log the issue, and do not partially mutate state.

Required validator/non-canon rule: Invalid runtime blocks gameplay proposals.

Required audit: Runtime failure entry in /debuglast or /stateaudit.

Required tests:

* invalid state fails softly
* invalid text fails softly
* context hook missing info does not crash
* hook never returns undefined

Risk if skipped: One bad hook call can corrupt state or crash the script.

⸻

5.2 TurnEngine

Original purpose: Track hook order, current turn, hashes, duplicate output, and hook lifecycle.

Old problem: Turn identity existed but was not cleanly separated from patch layers and output replay handling.

Decision: REWRITE IN MVP.

New owner: RuntimeHookContract + OperationLedger.

MVP or deferred: MVP blocker.

New implementation rule: Turn state must include current hook, turn index, input hash, output hash, last applied output hash, and command suppression flags.

Required validator/non-canon rule: Same output hash cannot apply the same consequences twice.

Required audit: Duplicate output replay audit.

Required tests:

* Retry/Continue replay does not duplicate item
* repeated output does not duplicate XP
* output hash skip works
* command output replay is ignored

Risk if skipped: Duplicate rewards, duplicate damage, duplicate card writes, duplicate XP.

⸻

5.3 CoreState

Original purpose: Create, validate, migrate, and repair root state.

Old problem: State shape changed across versions and required repair buckets/quarantine to survive bad data.

Decision: REWRITE IN MVP.

New owner: StateManager.

MVP or deferred: MVP.

New implementation rule: StateManager owns state.aidrpg, schema version, default creation, migration, integrity warnings, and safe missing-field repair.

Required validator/non-canon rule: No module writes state before StateManager initializes and validates it.

Required audit: State migration/repair audit.

Required tests:

* missing root initializes
* missing fields repair without deleting inventory
* malformed containers quarantine
* old version migration is idempotent

Risk if skipped: Old-state crashes, lost inventory, broken saves, version confusion.

⸻

5.4 PatchInventory / patch inventory record

Original purpose: Record late wrapper repairs and assign them back to core systems.

Old problem: Useful fixes were added late as wrapper layers instead of being native architecture.

Decision: DISCARD IMPLEMENTATION, KEEP TEST.

New owner: Old Fix Salvage Matrix + ReleaseCheck.

MVP or deferred: MVP planning artifact only.

New implementation rule: No PatchInventory runtime system. Its useful records become this matrix and permanent regression tests.

Required tests:

* no late hook wrapper changes version identity
* no patch layer bypasses CanonValidator
* old fixes mapped to owners

Risk if skipped: Old patch pile returns under new names.

⸻

5.5 EventPipeline

Original purpose: Convert text into event-like structures before consequences are applied.

Old problem: Event parsing and state mutation were not always cleanly separated.

Decision: REWRITE IN MVP.

New owner: EventScannerLite + ProposalBuilder.

MVP or deferred: MVP.

New implementation rule: EventScanner finds possible events only. ProposalBuilder creates EventProposal objects. Neither can mutate gameplay state.

Required validator/non-canon rule: All proposals must pass CanonValidator before reducers commit.

Required audit: Proposal list in /debuglast.

Required tests:

* output creates proposal, not direct item
* player input creates intent only
* parser cannot write inventory directly

Risk if skipped: Parser false positives directly corrupt state.

⸻

5.6 EventReducer

Original purpose: Apply detected events to state.

Old problem: Reducer boundaries were not always strict enough, and patch systems could mutate state outside the reducer flow.

Decision: REWRITE IN MVP.

New owner: ReducerRegistry + owner reducers.

MVP or deferred: MVP.

New implementation rule: ReducerRegistry routes only validated proposals to the owner reducer. Unknown owners hard-deny.

Required validator/non-canon rule: Reducers do not validate broad canon; they commit already-validated changes.

Required audit: Commit audit with owner reducer and dirty targets.

Required tests:

* unknown reducer rejected
* inventory event only InventoryReducer commits item
* quest reward eligibility does not directly mutate currency without routing

Risk if skipped: Multiple systems write the same truth and conflict.

⸻

5.7 CanonEligibilitySystem

Original purpose: Decide whether a hook/action/source can mutate canon.

Old problem: Good concept, but it lived as a broad guard rather than the central validator contract.

Decision: REWRITE IN MVP.

New owner: CanonValidator + Non-Canon Source Spec.

MVP or deferred: MVP.

New implementation rule: CanonValidator decides source eligibility, truth status, confidence, duplicate status, and ownership before any state mutation.

Required rules:

* input intent is not success
* output is proposal, not automatic truth
* context cannot mutate state
* Story Cards cannot mutate state
* command output cannot mutate state
* quoted/rumored/dream/hypothetical text cannot become confirmed truth

Required audit: ValidationResult for each proposal.

Required tests:

* card says player owns Crown; inventory unchanged
* context says quest active; quest state unchanged
* rumor death does not kill actor
* dream travel does not change real location

Risk if skipped: Non-canon text becomes real again.

⸻

5.8 ParserSafetySystem

Original purpose: Block parser false positives, especially quoted speech, failed attempts, wrong handoffs, and unsafe canon inference.

Old problem: It became a late quarantine/repair layer instead of first-class parser rules.

Decision: REWRITE IN MVP.

New owner: Parser Rulebook v1 + EventScannerLite + CanonValidator.

MVP or deferred: MVP blocker before parser expansion.

New implementation rule: Every parser hit must carry flags for completedAction, negated, hypothetical, quotedSpeech, dreamOrVision, rumorOrClaim, attemptOnly, failedOrRevoked, and confidence.

Required tests:

* quoted item command rejected
* failed ability does not stabilize
* negated pickup does not add item
* hypothetical item does not add item
* actual handoff accepted

Risk if skipped: The old false-positive bugs return immediately.

⸻

5.9 LongRunStabilitySystem

Original purpose: Prevent long-run state rot, bloated logs, stale candidates, and accumulated unsafe pending data.

Old problem: Stability was added after complexity instead of designed into queues, budgets, and cleanup.

Decision: REWRITE IN MVP.

New owner: CleanupManagerLite + Dirty Queue Spec + Performance Budget Spec.

MVP or deferred: MVP for basic cleanup; full long-run testing deferred to Whole-System Tester.

New implementation rule: Cleanup is budgeted, conservative, audited, and never creates truth.

Required tests:

* old visible loot clears after scene change
* important actor retained
* audit logs capped
* dirty queue capped
* cleanup does not invent item/quest/XP

Risk if skipped: Long campaigns slowly rot and become untrustworthy.

⸻

5.10 CoreAuthoritySystem

Original purpose: Centralize truth authority and prevent broad patch systems from writing state.

Old problem: Authority existed late and had to police already-existing broad systems.

Decision: REWRITE IN MVP.

New owner: CanonValidator + ReducerRegistry + StateManager.

MVP or deferred: MVP.

New implementation rule: One owner per truth type. Broad systems cannot directly write gameplay state.

Required audit: /releasecheck must fail if multiple writers exist for XP, HP, items, quests, cards, or context.

Required tests:

* parser cannot directly mutate inventory
* CardSync cannot mutate gameplay state
* ContextBuilder cannot mutate gameplay state
* releasecheck detects missing owner boundaries

Risk if skipped: Patch pile returns through “helper” systems.

6. Cross-cutting safeguards that must be preserved

6.1 No broad patch systems

Old broad systems like final polish, hardening, continuity, and repair layers must become tests, audits, or specific owner rules.

No future system may be allowed to say:

I repair everything after the fact.

Every repair must have an owner and test.

⸻

6.2 No direct parser writes

All old parser-style behavior must become:

raw text -> scanner hit -> EventProposal -> CanonValidator -> owner reducer

Never:

raw text -> inventory/quest/XP mutation

⸻

6.3 No card-to-canon path

CardSync, protected cards, generated cards, card UI, ability cards, and old managed cards must never become event sources.

⸻

6.4 No hidden live CardSync

Live CardSync writes require explicit safe mode exit, dry-run success, singleton contract, API adapter, and card tests.

Generated cards stay off until beta.

⸻

6.5 No cleanup that invents or deletes truth

Cleanup can prune stale temporary records and logs.

Cleanup cannot create XP/items/quests/actors/cards, and cannot delete active important truth.

⸻

6.6 No command dishonesty

If the feature is partial, /help must say partial.

If the feature is disabled, command output must say disabled.

If CardSync skipped due to budget, card audit must say skipped.

10. Final Gap Chunk A doctrine

The old systems were not useless.

They were evidence.

They proved what breaks.

This matrix keeps that evidence without keeping the unstable patch pile.

The new build must not be:

old code + more patches

It must be:

old lessons -> clean rules -> owner modules -> validation -> reducers -> audits -> tests

That is how the project avoids restarting the same cycle.
