# AIDRPG Production Chunk 10 — Formula Matrix and Progression Baseline

## 0. Document status

**Document name:** AIDRPG Production Chunk 10 — Formula Matrix and Progression Baseline  
**Production sequence:** 10 of 25 remaining production chunks  
**Build target:** WorldLedger V0.17.9 place/time-depth accepted build / AIDRPG Core MVP expansion path  
**Purpose:** Deepen XP, level, progression events, formula registry, progression history, stat-baseline placeholders, and world-scaling boundaries without vague XP, duplicate XP, hidden rubber-band scaling, or unsafe stat automation.  
**Status:** Core systems production chunk.  
**Follows:** Production Chunk 09 — Place, Travel, Time, Scene, and Deadline Depth.  
**This document does not contain final script code.**

Production Chunk 10 exists because progression is where many RPG systems silently become unfair, inconsistent, or impossible to test.

Old attempts and rough builds often risked:

```text
vague “learning experience” becoming XP
ability training awarding XP automatically
quest reward promises granting XP before payment/completion
repeat outputs duplicating XP/levels
level formulas changing mid-save
stats increasing without owner/rule/test support
world enemies rubber-banding to player level
high-level numbers becoming meaningless
manual /setlevel shortcuts corrupting balance
```

This chunk creates the formula and progression baseline.

It does **not** build the full final stat engine yet.

It makes progression deterministic, source-bound, duplicate-safe, inspectable, and ready for Production Chunk 11.

---

# 1. Chunk doctrine

```text
Vague experience is not XP.
Training is not XP unless an exact XP event says so.
Quest promise is not XP.
Quest completion is not XP unless reward/XP event is accepted.
Level does not change without formula authority.
Stats do not change without owner rules.
World threat does not rubber-band to player level.
Duplicate output cannot duplicate XP.
Formula changes must be versioned.
```

Progression truth must be formula-driven, versioned, repeat-safe, and explainable.

# 14. XP source rules

Accepted XP sources:

```text
safe output explicitly says “You gain 20 XP.”
validated quest reward payment/completion produces exact XP reward and ProgressionReducer is active
structured startup exact XP if before lock and source is safe
future combat reward if Combat Event Model supports it
future system award if owner/rule/test/gate exists
```

Rejected XP sources:

```text
You learn from the experience.
This was a valuable experience.
You feel stronger.
You are more skilled now.
The quest promises 20 XP.
The quest board lists 20 XP.
[AIDRPG] XP: +20.
Context says you gained 20 XP.
Story Card says the player is level 10.
```

Pending/deferred XP sources:

```text
quest promises XP but not paid/completed
teacher says training will make you stronger
long training montage without exact XP
combat victory without XP rule active
```

# 20. Progression CanonValidator expansion

CanonValidator must enforce XP/progression safety.

## 20.1 Accept XP gain when

All are true:

```text
source is safe story output or safe structured startup
local clause explicitly says exact numeric XP gained/awarded/received
target is progression/XP, not vague experience
amount is positive number
not promised/ready/listed/deferred only
not command/context/card/audit/debug source

```

## 20.2 Reject XP gain when

Any are true:

```text
vague experience
feels stronger
training only
quest promise only
quest board listing only
combat victory without XP event
output command/debug/context/card source
negative or nonnumeric amount
manual command
```

## 20.3 Accept level-up when

```text
formula profile active and XP threshold crossed
or safe structured startup explicitly sets level before lock
or future owner/rule/test/gate supports level change
```

## 20.4 Reject level-up when

```text
Story Card says level 10
command says level 10
context says level 10
NPC boasts you are level 10
manual /setlevel in MVP
formula profile missing and no safe structured source
```

## 23.1 XP gain commit

Accepted XP gain should:

```text
1. Confirm validation accepted.
2. Confirm safe source and exact positive amount.
3. Confirm operation key.
4. If duplicate, return skipped_duplicate.
5. Add XPEventRecord.
6. Increase totalXP/currentXP according to formula profile.
7. Add operation key.
8. Check level-up only if formula profile active.
9. Mark progression/player_sheet/context dirty.
10. Audit compactly.
```

## 23.2 Level-up commit

If formula profile active and threshold crossed:

```text
calculate new level
create LevelEventRecord
update level/xpToNext
record levelHistory
mark player_sheet/progression/context dirty
```

Do not assign stats automatically in PC10.

## 23.3 Formula profile commit

Accepted formula profile setup should:

```text
set formulaProfile
set formulasEnabled according to profile
lock profile if safe
record FormulaRuleRecords or profile reference
write audit/migration note
```

Do not silently change locked profile.

## 23.4 Milestone commit

Accepted milestone should:

```text
create ProgressionMilestoneRecord
not grant stats/XP unless separate accepted event exists
```
