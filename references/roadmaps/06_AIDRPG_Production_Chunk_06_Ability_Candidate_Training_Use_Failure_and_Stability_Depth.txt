# AIDRPG Production Chunk 06 — Ability Candidate, Training, Use, Failure, and Stability Depth

## 0. Document status

**Document name:** AIDRPG Production Chunk 06 — Ability Candidate, Training, Use, Failure, and Stability Depth  
**Production sequence:** 06 of 25 remaining production chunks  
**Build target:** WorldLedger V0.17.5 inventory-depth accepted build / AIDRPG Core MVP expansion path  
**Purpose:** Deepen ability records, training evidence, use evidence, failed attempts, candidate/unstable/stable separation, naming safety, duplicate-use protection, and ability command/context display without false ability unlocks.  
**Status:** Core gameplay-depth production chunk.  
**Follows:** Production Chunk 05 — Inventory, Equipment, Scene Items, and Custody Depth.  
**This document does not contain final script code.**

Production Chunk 06 exists because ability handling was one of the easiest places for old builds to become corrupted.

The system must never again treat every ability mention, output title, quote, dream, failed attempt, or training phrase as stable mastery.

Abilities must grow through validated evidence.

Training can create candidates. Repeated use can build evidence. Failures can be recorded without becoming unlocks. Only validated stabilization can create a stable ability.

---

# 1. Chunk doctrine

```text
Mentioned is not learned.
Named is not mastered.
Tried is not stable.
Failed is not unlocked.
Pretended is not usable.
Quoted is not known.
Dreamed is not real mastery.
Training is evidence, not automatic mastery.
Output-only “You learned X” is not enough by default.
Only validated stabilization creates a stable ability.
```

Ability truth must be conservative, evidence-based, duplicate-safe, and explainable.

---

# 2. Why this chunk comes now

Production Chunk 05 made inventory reliable. Abilities come next because later combat, progression, race/lineage powers, spellcasting, cooldowns, failures, quest abilities, and world-threat interactions all depend on clean ability state.

If abilities are not safe now, later systems will repeatedly create junk powers, duplicate evidence, false mastery, and broken progression.

# 8. Ability status transition model

## Hint to candidate

Allowed when the ability is mentioned with plausible training/use relevance, the player trains toward it, or a teacher/source discusses it as a real technique. No stable mastery yet.

## Candidate to unstable

Allowed when repeated training evidence exists, first unstable manifestation/use success exists, or validator marks unstable/candidate manifestation.

## Candidate/unstable to stable

Allowed only when CanonValidator accepts `ability.stabilize_candidate` or equivalent.

Strong sources may include:

```text
validated startup structured ability
teacher/training culmination plus demonstration
successful controlled manifestation
validated source-grant/transformation event
future mini-spec source such as absorption/evolution when enabled
```

## Any status to sealed/unavailable

Allowed from direct validated sealing/unavailability event or setup marking. Sealed/unavailable does not delete history.

# 9. AbilityNameSanitizer depth

AbilityNameSanitizer must be owner-specific and must not leak into shared cleanup.

It must clean:

```text
I train Ember Ward to protect allies from heat -> Ember Ward
I practice Frost Step by moving across slick stones -> Frost Step
I drill Stoneguard until my stance holds under impact -> Stoneguard
I train Moonblade by practicing careful crescent cuts -> Moonblade
I refine Crimson Lotus Fang through repeated strikes -> Crimson Lotus Fang
```

It must preserve meaningful ability names:

```text
Shield Against Dawn
Step Across Stars
Song for the Dead
Blade of the North
Ward from Below
```

It must not create abilities from non-ability actions:

```text
I travel to the smithy -> no smithy ability
I inspect the old wooden door -> no door ability
I use the iron key on the cellar door -> no key/door ability
I ask Mara about Moonblade -> hint/reference only unless training/use context exists
```

# 11. Ability CanonValidator expansion

Accept training evidence only when:

```text
source is safe input intent or safe story output
local clause has clear training/practice/refinement intent
ability target is bound by AbilityNameSanitizer
not pretend-only
not quoted-only
not dream-only
not denied/no usable technique
not command/context/card/audit/debug source
```

Training normally creates or updates candidate/evidence. Training does not create stable mastery by default.

Accept use success evidence only when:

```text
safe story output confirms ability use or manifestation succeeded
ability target is bound
not dream/quote/pretend/metaphor only
not failed/collapsed/no effect
operation key not duplicate
```

Use success may add evidence and reliability, but it does not automatically stabilize unless a separate stabilize result is accepted.

Accept use failure evidence when:

```text
safe input/output states attempt/failure/collapse/no effect
ability target is bound
not command/context/card source
```

Failure evidence must not create stable mastery.

Accept stable ability only when:

```text
structured startup ability before lock
validated teacher/training culmination
successful controlled demonstration with stabilization wording
validated grant/source event
future enabled mini-spec event
```

Reject stable ability when:

```text
output-only unsupported “You learned X”
quoted instruction only
dream/vision only
pretend use
failed/collapsed/no effect
scroll/book/title only
rumor only
manual command output
context/card/audit/debug source
input attempt only with no output support
non-ability target
wrong sanitizer used
```

# 12. Critical old-failure rules

## Output-only learning rule

Example:

```text
You learned Moonblade.
```

Default result:

```text
pending or rejected unsupported learning claim
no stable ability
no direct AbilityReducer stable commit
```

It may become evidence only if surrounding context supports it through training arc, teacher confirmation, demonstration, startup, or source-grant.

## Failed ability rule

Examples:

```text
You attempt Void Lantern Veil, but it collapses.
Azure Dragon Step flickers and fails.
Your spell fizzles with no effect.
```

Expected:

```text
failure evidence recorded
status may remain candidate/unstable/failed_only
stable ability not created
```

## Pretend / quote / dream rules

```text
You pretend to use Azure Dragon Step. -> no real ability use
Mira says, "Use Hollow Star Palm." -> hint/reference only
In a dream, you master Star Chain. -> no real stable ability
```

# 15. AbilityReducer detailed behavior

AbilityReducer owns:

```text
abilities.records
abilities.stable
abilities.unstable
abilities.candidates
abilities.hints
abilities.failed
abilities.sealed
abilities.unavailable
abilities.evidenceLog
abilities.warnings
```

Hint commit:

```text
create/update ability hint record
status hint unless stronger existing status exists
record evidence type hint
not make usable/stable
mark abilities/context dirty
audit compactly
```

Training commit:

```text
create/update ability record
status candidate unless existing status stronger
append training evidence
increment trainingCount
record sourceOperationKey
mark abilities/context dirty
audit compactly
```

Use success commit:

```text
append use_success evidence
increment useCount and successCount
increase reliability label if policy exists
keep status candidate/unstable unless stabilize event is accepted
mark abilities/context dirty
```

Use failure commit:

```text
append use_failure evidence
increment useCount and failureCount
set or keep status candidate/unstable/failed_only as appropriate
not create stable ability
mark abilities/context dirty
```

Stabilize commit:

```text
require validationResult.eventType = ability.stabilize_candidate or equivalent
check durable operation key
set status stable
add to stable list
remove from candidate/unstable display lists if needed
preserve evidence history
mark abilities/context dirty
audit high-importance line
```

Sealed/unavailable commit:

```text
set status sealed or unavailable
record reason
preserve evidence/history
mark abilities/context dirty
```

```text
Abilities are records with evidence and status.
```
