# AIDRPG Production Chunk 11 — Stats, Derived Values, Conditions, and Invariant Checker

## 0. Document status

**Document name:** AIDRPG Production Chunk 11 — Stats, Derived Values, Conditions, and Invariant Checker  
**Production sequence:** 11 of 25 remaining production chunks  
**Build target:** WorldLedger V0.17.10 progression-baseline accepted build / AIDRPG Core MVP expansion path  
**Purpose:** Deepen base stats, stat modifiers, derived values, resource formulas, condition modifiers, invariant checking, stat audit, and safe repair/quarantine behavior without vague stat gains, hidden recalculation drift, impossible values, or cleanup deleting truth.  
**Status:** Core systems production chunk.  
**Follows:** Production Chunk 10 — Formula Matrix and Progression Baseline.  
**This document does not contain final script code.**

Production Chunk 11 is the math-safety wall between the progression baseline and the combat system. It makes stats useful while preventing the classic failure pattern where vague narration, cleanup, or a stale formula silently rewrites the character.

---

# 1. Chunk doctrine

```text
Base stats are truth.
Derived stats are calculated snapshots.
Modifiers need source, owner, duration, status, and operation keys.
Conditions may affect stats, but cleanup cannot heal them.
Level does not grant stats unless a stat rule exists.
Vague strength is not STR.
Feeling faster is not DEX.
Training is not a stat increase by default.
Impossible values must warn, repair structurally, or quarantine.
No derived value becomes permanent truth without formula authority.
```

Stats must be deterministic, versioned, explainable, and ready for AI Dungeon gameplay, where output text can be messy and repeated.

---

# 2. Why this chunk comes now

Production Chunk 10 locked exact XP, formula profile authority, duplicate-safe level events, and no-rubber-band world scaling. Stats come next because future systems depend on them:

```text
combat damage/healing
body resources
ability costs and reliability
conditions and injuries
race/form consequences
creature threat comparison
world threat benchmarks
equipment modifiers
long-run balance
```

If stats and invariants are not safe before combat, combat will be built on unstable math and patch-loop risk.

# 4. Stat authority model

Every stat value must have an authority level:

```text
unknown
setup_confirmed
formula_derived
validated_story_change
temporary_modifier
condition_modifier
equipment_modifier_deferred
race_form_modifier_deferred
manual_deferred
invalid_quarantined
```

Rules:

```text
unknown does not become 10 by default unless the active profile says so
setup_confirmed can initialize base stats before lock
formula_derived calculates snapshots but does not overwrite base stats
validated_story_change requires strict validation and ReleaseCheck coverage
temporary_modifier must have source/duration/status
condition_modifier must link to an active condition/injury
manual_deferred is blocked/display only, not active mutation
```

# 14. CanonValidator stat/modifier rules

Accept setup stat initialization only when:

```text
structured startup source before lock
stat profile active or setup schema explicitly supports stats
stat value numeric and within allowed range
operation key present
```

Reject stat change when any are true:

```text
vague stronger/faster/smarter phrasing
training-only claim
ability use claim
dream/quote/rumor/prophecy
command/context/card/audit/debug source
manual command
impossible negative/nonnumeric value
formula profile missing for formula-derived change
```

Accept modifier only when:

```text
active condition/injury/status exists or is accepted in same batch
modifier mapping rule exists
source is safe
operation key present
```

Reject modifier when:

```text
condition is only rumored/quoted/dreamed
source is command/context/card/audit/debug
equipment/race/ability modifier tries to activate before its owner chunk
```

# 15. DerivedValueCalculator behavior

DerivedValueCalculator should:

```text
read base stats
read active modifiers
read formula rules
calculate derived values
write derivedSnapshot only through owner reducer/checker path
mark stale if inputs change
never mutate base stats
never mutate active conditions
never award resources as healing
```

If formula missing:

```text
derived value remains unknown/deferred
ReleaseCheck WARN if feature claimed active
```

# 16. InvariantChecker behavior

InvariantChecker should run after reducer batches and through diagnostic commands.

It should check:

```text
required stat structures exist
base stat values valid
resource current/max valid
modifiers have source/status/duration
condition modifiers link to active conditions
expired modifiers inactive
derived values match inputs if active
level/formula profile consistency
no duplicate active modifiers without stacking policy
no command/card/context source as stat truth
cleanup protected paths intact
```

Allowed checker actions:

```text
report warning
clamp structural resource overflow
quarantine malformed modifier/stat record
mark derivedSnapshot stale
block ReleaseCheck
```

# 17. ProgressionReducer stat-safe hooks

ProgressionReducer may interact with stats only through explicit stat rules.

Allowed:

```text
on level-up, check stat formula profile

```

Forbidden:

```text
level-up automatically gives random stat points
level-up heals to full by default
level-up changes HP max without resource formula

```

# 18. Body/resource integration

Rules:

```text
maxHP/maxMP/maxEP may derive from stats/formulas
currentHP/currentMP/currentEP does not auto-fill to new max unless policy active
structural clamp from above max is not healing
if max decreases below current, current clamps down structurally with audit
if max increases, current remains same unless heal/recovery/fill policy is accepted
```

This prevents false healing from formula recalculation.

Ability modifiers:


# 27. Pass / warn / fail criteria

## PASS

```text
stat structures exist and are source-aware
base stats and derived values are separated
modifiers have source/status/duration/keys
condition modifiers link to active conditions
derived values recalculate from formula inputs only
resource max/current recalculation does not heal by default
level-up does not assign stats without formula authority
vague/training/command/card/context stat gains are rejected
InvariantChecker detects impossible values and records actions
cleanup preserves active stat/body/formula truth
stats display honestly
PC11 tests pass
ReleaseCheck has no PC11 FAIL/BLOCKED gates
```

## WARN

```text
stats remain unknown because no profile is active
stat formulas are partially deferred
combat derived values are deferred
race/form/equipment modifiers are deferred
derived snapshots are display-only until combat formulas activate
```

## FAIL

```text
unknown stats default silently
vague narration increases stats
training increases stats by default
command/context/card text mutates stats
level-up assigns stats without formula authority
resource max increase heals current HP/MP/EP by default
derived values overwrite base stats
condition cleanup removes active penalties
modifiers duplicate without stacking policy
world enemies scale from player stats
InvariantChecker repairs gameplay truth by awarding/healing/deleting active state
```
