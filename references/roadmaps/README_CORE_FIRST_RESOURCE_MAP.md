# WorldLedger Core-First Current Planning Resource

This package is organized so a future pass can see the intended direction clearly:

1. The changes are meant to affect the WorldLedger clean core through the authorized pipeline and owner modules.
2. Current plans and roadmap documents are kept near the front.
3. Older scripts, test packages, and salvage material are preserved instead of ignored, but they are separated from active authority.
4. Rejected/failure references are retained only as failure/test evidence, not as a build base.

## Read order

1. `01_CORE_AUTHORITY_AND_BUILD_LAW/WorldLedger_Clean_Core_Build_Control.docx`
2. `00_START_HERE/CORE_CHANGE_HANDOFF.md`
3. `03_CURRENT_PLANS_AND_SEQUENCE/WorldLedger_Roadmap_Backlog_v9_4.json`
4. `03_CURRENT_PLANS_AND_SEQUENCE/WorldLedger_Master_Roadmap_Salvage_Integration_Plan_v9_4.md`
5. `02_CURRENT_CORE_CHANGE_TARGETS/WorldLedger_CleanCore_Build9_6B2_EconomyTransactionFoundation.txt`
6. `02_CURRENT_CORE_CHANGE_TARGETS/FinalWLCore.txt`
7. Then consult salvage/history/tests as needed.

## Folder intent

- `01_CORE_AUTHORITY_AND_BUILD_LAW`: rules that control how core changes are allowed to happen.
- `02_CURRENT_CORE_CHANGE_TARGETS`: current files that represent active or near-active changes to the core.
- `03_CURRENT_PLANS_AND_SEQUENCE`: current plans, backlog, sequencing, and salvage integration.
- `04_CORE_BUILD_HISTORY_AND_PRIOR_PHASES`: prior clean-core build progression.
- `05_SALVAGE_REFERENCE_NOT_ACTIVE_BASE`: useful older references that must not override current authority.
- `06_REJECTED_FAILURE_REFERENCE_DO_NOT_BASE`: rejected builds retained only for failure evidence/regression tests.
- `07_TEST_ACCEPTANCE_AND_REGRESSION_RESOURCES`: QA, regression, and acceptance resources.
- `08_SUPPORTING_PACKAGES_AND_EXTRACTED_ARCHIVES`: other packages and extracted supporting materials.
- `09_OTHER_SUPPORTING_REFERENCE`: material that did not fit the above categories but is still preserved.
- `99_MANIFESTS_AND_PACKAGE_AUDIT`: package manifests, hashes, duplicate log, and verification details.
