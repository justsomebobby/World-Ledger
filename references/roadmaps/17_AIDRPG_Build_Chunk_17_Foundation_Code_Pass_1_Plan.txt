AIDRPG Build Chunk 17 — Foundation Code Pass 1 Plan

0. Document status

Document name: AIDRPG Build Chunk 17 — Foundation Code Pass 1 Plan
Build target: AIDRPG Core MVP v0.1 / final-core architecture path
Purpose: Define the exact first real script generation scope, assembly order, shell boundaries, disabled systems, test order, package strategy, and no-overbuild limits before actual code is created.
Status: Final pre-code planning chunk.
Follows: Build Chunk 16 — ReleaseCheck and Regression Matrix Lock.
This document does not contain final script code.

This chunk is the transition point from planning into implementation.

The purpose of Code Pass 1 is not to build the entire final dream system.

The purpose of Code Pass 1 is to build the safe foundation that prevents old failure classes from returning.

If Code Pass 1 is too ambitious, it will become another patch pile.

If Code Pass 1 is too vague, it will repeat old bugs.

This plan defines the exact safe middle path.

⸻

1. Code Pass 1 doctrine

Build the foundation first.
Make unsafe systems impossible by default.
Make every command honest.
Make every hook fail softly.
Make every state bucket stable.
Make parser/proposal/validator/reducer boundaries real.
Make support layers non-canon.
Make ReleaseCheck tell the truth.
Do not overbuild deferred systems.

Code Pass 1 should create a working, installable, inspectable script foundation.

It should not pretend to be a complete automation game engine yet.

⸻

2. Code Pass 1 success definition

Code Pass 1 is successful when the script can:

initialize state safely
repair missing state buckets safely
run AI Dungeon hooks without crashing
route commands safely
render commands honestly
suppress command output from story parsing
track duplicate output hashes
run parser/proposal/validator/reducer shells safely
commit only limited accepted MVP-safe events if enabled
or shell-skip commits honestly if disabled
record audits and ledger keys
keep context read-only
keep CardSync dry-run/safe
keep generated cards disabled
quarantine unsafe old data
cap logs and dirty queues
run /releasecheck honestly

The first code pass is allowed to be conservative.

It is not allowed to lie.

⸻

full combat automation

complete level 1–1000 stat engine

18. Reducer implementation scope

Code Pass 1 may implement limited reducers, but they must be real where they commit.

Must commit safely:

Must reject unsafe routed flags.

18.2 AbilityReducer

Must commit safely:

Must not create stable ability from output-only unsupported claim.

18.3 BodyReducer

Must commit safely:

Must not set death from rumor/quote/dream.

18.4 QuestReducerLite

Must commit safely:

Reward/currency policy must be explicit. Prefer split owner policy.

18.5 ActorReducerLite

Must commit safely:

18.6 PlaceReducerLite

Must commit safely:

current scene confirmation
strong arrival
travel intent
weak references as references only

18.7 TimeReducerLite

May commit cautiously:

literal time advance text
deadline notes

Age mutation may remain pending unless age policy is fully coded.

18.8 ProgressionReducerLite

Can be shell/limited:

22. Hook orchestration for Code Pass 1

Input hook:

StateManager.init
Runtime.beginHook
if command -> CommandRouter.safeRoute -> Runtime.setCommandSuppression -> return command output
else mark input, maybe parser intent shell, lock startup if first gameplay input, return input
Runtime.endHook/failSoft

Context hook:

StateManager.init
Runtime.beginHook
ContextBuilderLite.build read-only packets
Runtime.endHook/failSoft
return context text

Output hook:

StateManager.init
Runtime.beginHook
if command output suppressed -> skip scan, return output
if duplicate output -> skip consequences, return output
EventScannerLite.scanOutput
ProposalBuilder.fromHits
CanonValidator.validateAll
ReducerRegistry.applyAcceptedBatch
DirtyQueue.add from reducer results
CardSyncLite dry-run/shell if dirty cards
CleanupManagerLite.safeCaps
Runtime.markOutputApplied
Runtime.endHook/failSoft
return original output

33. Final Build Chunk 17 doctrine

Foundation Code Pass 1 must be boring, strict, and safe.

It should not try to impress by activating every dream feature.

It should impress by not repeating old failures.

Final rule:

Build the core truth pipeline first.
Disable what is not safely specified.
Make every unsafe source non-canon.
Make every state mutation go through validation and owner reducers.
