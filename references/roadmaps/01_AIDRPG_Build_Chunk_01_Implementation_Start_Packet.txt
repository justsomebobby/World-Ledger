2. Purpose of Core MVP v0.1

Core MVP v0.1 exists to create a trustworthy engine foundation.

It must prove that the script can:

* initialize state safely
* preserve state safely
* expose honest commands
* isolate command output from story parsing
* track runtime hook metadata
* fail softly instead of crashing
* keep Context read-only
* keep Story Cards mirror-only
* keep generated cards disabled
* prepare the proposal/validation/reducer architecture without overbuilding it
* prevent duplicate operation application
* provide debug/audit surfaces

Core MVP v0.1 is successful only if it is boring, stable, inspectable, and safe.

⸻

3. What Core MVP v0.1 is not

Core MVP v0.1 is not:

* the final game system
* full combat automation
* full XP/stat progression automation
* generated Story Card automation
* economy
* crafting
* investigation
* reputation/faction simulation
* domain/labor management
* absorption/evolution
* multi-protagonist play
* large-scale warfare
* full body compatibility simulation
* full advanced ability formation
* full party/summon system
* full migration resolver for every old save shape

Those are later systems.

They are not allowed in the first build.

6. First build goal in one sentence

Core MVP v0.1 must build the smallest stable truth engine that can initialize, inspect, audit, and protect state without enabling advanced gameplay automation too early.

⸻

7. Core safety doctrine for v0.1

The first build must obey this doctrine:

Input may intend.
Context may remind.
Output may propose.
CanonValidator may approve.
Reducers may commit.
OperationLedger may dedupe.
Cards may mirror.
Commands may inspect.
Audits must explain.

This means:

* player input does not automatically succeed
* context text does not mutate state
* command output does not mutate state
* Story Cards do not create canon
* generated cards are disabled
* parser hits are not direct state changes
* all meaningful mutations eventually go through owner reducers
* duplicate operations must be skipped

AIDRPG Core MVP v0.1 is foundation-focused.

/cardaudit

Must say whether CardSync is:

dry-run
safe mode
live protected writes disabled
generated cards disabled

/releasecheck

Must not say PASS if required safety buckets are missing.

Disabled commands

Must not crash.

Example:

/craft is disabled in MVP. Crafting requires the Crafting Mini-Spec and later build phase.

33. Required first tests

Core MVP v0.1 must pass these first tests before expanding.

BC1-001 — Fresh state initializes

Given missing state.aidrpg, run script.

Expected:

* root state created
* required buckets exist
* generatedCardsEnabled false
* no crash

BC1-002 — Missing bucket repairs safely

Given state with missing inventory bucket but valid player data.

Expected:

* inventory bucket added
* player data preserved
* repair warning logged

BC1-003 — /help is honest

Run:

/help

Expected:

* active commands listed
* disabled systems listed
* no false claims about generated cards/economy/crafting

BC1-004 — Commands do not mutate gameplay

Run:

/inventory
/quests
/abilities

Expected:

* output displays state
* no new item/quest/ability created

BC1-005 — Command output suppression exists

Run /inventory displaying an item.

Expected:

* item does not duplicate from command output
* suppression flag/audit exists

BC1-006 — Runtime fail-soft exists

Simulate safe internal error.

Expected:

* valid return shape
* runtime warning/error logged
* state not erased

BC1-007 — Generated cards disabled

Check state and /cardaudit.

Expected:

* generatedCardsEnabled false
* generated creates per turn 0
* card audit says disabled

BC1-008 — OperationLedger exists

Check /ledger or /releasecheck.

Expected:

* permanentKeys, recentKeys, rewardKeys, cardKeys, sourceUseKeys exist

BC1-009 — /releasecheck catches unsafe flag

Set generatedCardsEnabled true in test state.

Expected:

* /releasecheck FAIL

BC1-010 — Context declared read-only

Run Context hook or /contextaudit placeholder.

Expected:

* no gameplay mutation
* audit says read-only guard present

34. First blocker failures

Core MVP v0.1 cannot be considered ready if any of these are true:

* root state does not initialize
* commands crash
* /help lies about active systems
* generatedCardsEnabled is true
* command output can create items/quests/abilities
* Story Cards are treated as canon
* Context can mutate gameplay state
* OperationLedger buckets are missing
* /releasecheck missing or dishonest
* missing-field repair erases valid state
* deferred systems are active
