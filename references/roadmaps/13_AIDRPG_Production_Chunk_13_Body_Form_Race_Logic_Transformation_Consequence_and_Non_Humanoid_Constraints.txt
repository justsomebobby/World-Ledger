# AIDRPG Production Chunk 13 — Body Form, Race Logic, Transformation Consequence, and Non-Humanoid Constraints

## 0. Document status

**Document name:** AIDRPG Production Chunk 13 — Body Form, Race Logic, Transformation Consequence, and Non-Humanoid Constraints  
**Production sequence:** 13 of 25 remaining production chunks  
**Build target:** WorldLedger V0.17.12 combat-event accepted build / AIDRPG Core MVP expansion path  
**Purpose:** Deepen race/species identity, current form, transformation events, body traits, form capabilities, non-humanoid constraints, form consequences, and form-aware display/context without identity drift, fake transformations, or unsafe power grants.  
**Status:** Core systems production chunk.  
**Follows:** Production Chunk 12 — Combat Event Model and Damage/Healing Dispute Resolver.  
**This document does not contain final script code.**

Production Chunk 13 is where form finally starts to matter.

This is the chunk that lets the game support things like wolf form, winged form, scaled body, ghostly partial form, large monster body, tiny familiar body, water-breathing form, clawed hands, no hands, tail balance, horns, fur, shell, nonhuman speech limits, and nonhuman tool limits.

But it must do this without repeating the old failure loops:

```text
current form overwriting true identity
illusion becoming body truth
disguise becoming species
rumor becoming lineage
dream transformation becoming real
race label granting full powers
non-humanoid body still using every human tool normally
cleanup deleting active form consequences
combat damage proving a race power without validation
card/context text changing body truth
```

This chunk should feel fun in gameplay because forms and bodies create real consequences.

It should also be strict because identity/body corruption can break every future system.

---

# 1. Chunk doctrine

```text
True race/species is not current form.
Current form is not disguise.
Disguise is not illusion.
Illusion is not body truth.
Temporary transformation is not permanent identity.
Rumor is not lineage.
Dream form is not real form.
Cosmetic label is not physical capability.
Physical form must create physical constraints.
Non-humanoid bodies must not behave like default humans.
Race/lineage labels do not grant powers without validated rules.
```

Form should be playable, visible, and consequential.

But every form truth must have source, duration, owner, rollback behavior, and tests.

---

# 2. Why this chunk comes now

Production Chunk 12 created safe combat event handling.

Body form comes next because future systems depend on it:

```text
equipment compatibility
inventory carrying/use constraints
combat reach, bite, claws, wings, size, posture
ability use and spellcasting limitations
social reaction and witness memory
creature ecology
race/species world rules
transformation powers
absorption/evolution later
world bible race/creature references later
encounter threat logic
party/summon forms later
```

If form/race logic is not safe now, later world and combat systems will keep patching around identity drift.

```text

```

Rules:


# 18. Transformation fun rules

Forms should matter in ways that are fun and readable.

Allowed consequences in this chunk:

```text
wolf form: no human hands, altered speech, quadruped movement, scent-tracking label, bite/claw method label
winged form: visible wings, possible glide/flight deferred, armor/clothing warning
fish/amphibious form: water-breathing capability if validated, land movement warning if appropriate
large beast form: size access warning, armor/tool compatibility warning, intimidation visibility label
tiny familiar form: small tool/use warning, stealth/size label, carrying capacity warning
ghostly form: incorporeal/corporeal rules deferred unless validated, social alarm label
construct form: pain/bleeding logic deferred to creature/body chunks unless fully validated
undead form: death/bleeding/fatigue rules deferred unless race/body rule active
```

Not allowed automatically:

```text
free stat bonuses
free combat damage formulas
free spell powers
free social reputation shifts
free quest completion
free equipment transformation
free immortality
free flight mechanics without rules
```

# 19. Form CanonValidator expansion

CanonValidator must enforce form safety.

## 19.1 Accept physical transformation when

All are true:

```text
safe story output directly states physical body transformation
source is not command/context/card/audit/debug
not dream/vision-only
not quoted claim only
not disguise/illusion/cosmetic wording
target form is bound
physicality is clear enough
operation key not duplicate
```

Examples:

```text
Your bones crack and your body becomes a wolf.
Scales spread across your arms, hard and real beneath your fingers.
Your hands twist into claws, changing how you grip the sword.
```

## 19.2 Accept disguise/presentation when

```text
safe source states clothing/mask/makeup/behavior changes appearance
physical body does not change
```

Result:

```text
disguise/presentation active
no body constraints unless outfit itself affects movement/equipment later
```

## 19.3 Accept illusion when

```text
safe source states magical/perceptual appearance change
body remains physically same unless text directly says otherwise
```

Result:

```text
illusion active
social/perception label
no physical capabilities/constraints by default
```

## 19.4 Reject transformation when

Any are true:

```text
dream/vision only
rumor/prophecy only
quote says transformation happened
metaphor/simile only
pretend/roleplay only
command/context/card/audit/debug source
candidate/uncertain wording only
```

# 22. BodyReducer/FormLogic behavior

BodyReducer or FormLogic owns:

```text
player.currentForm
player.trueRaceSpecies references
player.lineage/candidate traits
body.bodyTraits
body.formConstraints
body.formCapabilities
body.formConsequences
body.formHistory
```

## 22.1 Physical transformation commit

Accepted transformation should:

```text
create TransformationEventRecord
create/update FormRecord
set currentForm to active physical form
add validated body traits
add derived constraints/capability labels
create duration record if known
mark player_sheet, body_status, context dirty
mark inventory_equipment/social_memory dirty if constraints/visibility changed
audit compactly
```

## 22.2 Partial transformation commit

Accepted partial change should:

```text
add body traits and constraints without replacing whole currentForm unless appropriate
preserve base form reference
record affected body parts
```

## 22.3 Reversion commit

Accepted reversion should:

```text
set active form inactive/reverted
restore previous/base form if known
end constraints/capabilities sourced from reverted form
preserve transformation history
mark dirty targets
```

## 22.4 Disguise/illusion commit

Accepted disguise/illusion should:

```text
create FormRecord type disguise or illusion
set presentation/illusion fields
not change physical currentForm
not add physical constraints unless explicitly physical
```

## 22.5 Race/species commit

True race/species change is protected.

Allowed only from:

```text
structured startup before lock
explicit validated permanent species transformation with strict policy
future migration/override spec
```

Default:

```text
store candidate/pending lineage/species traits
do not overwrite trueRaceSpecies
```

# 24. Non-humanoid constraint behavior

Non-humanoid constraints should affect display/context and future validation.

## 24.1 Hands and tool use

If form has no human hands:

```text
/sheet and /status show limited/no human hands
/inventory may warn equipped humanoid weapons/tools are awkward/deferred
context reminds model not to assume normal tool use
```

Do not delete items or unequip automatically unless future equipment policy supports it.

## 24.2 Speech

If form cannot speak normally:

```text
context should say speech is altered/limited
actor/social systems may later react if witnessed
commands remain available out-of-story
```

## 24.3 Movement

If quadruped, winged, aquatic, tiny, or huge:

```text
context should include movement constraints
place/travel validators may later use them
```

## 24.4 Combat method labels

Claws/bite/tail may become combat method labels.

```text
bite/claw can be attack method
no automatic damage formula
combat still validates attempts/hits/damage
```
