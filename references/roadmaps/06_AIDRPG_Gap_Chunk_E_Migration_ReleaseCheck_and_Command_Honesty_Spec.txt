AIDRPG Gap Chunk E — Migration, ReleaseCheck, and Command Honesty Spec

0. Document status

Document name: AIDRPG Gap Chunk E — Migration, ReleaseCheck, and Command Honesty Spec
Purpose: Define how AIDRPG repairs old/polluted state, quarantines unsafe legacy data, reports readiness through /releasecheck, and keeps commands honest before coding begins.
Status: Pre-code blocker.
Applies after: Gap Chunk D — Parser Rulebook, Resolver, and Name/Trigger Policy.
Applies before: Script v0.1 coding, old-save migration, live CardSync, command implementation, and any public release check.
This document does not contain final script code.

This chunk exists because old AIDRPG/TASIS versions created many safety-related command and migration problems:

* old state shapes changed across versions
* duplicate managed cards could exist
* old Story Card text could contain false canon
* old generated cards could have junk triggers
* protected cards could be manually edited or duplicated
* old commands could claim systems worked when they were partial
* debug/finalcheck commands could be inconsistent
* setup/import could overwrite player identity
* old polluted saves could carry malformed data
* cleanup could remove or preserve the wrong things
* migration could accidentally create truth from card prose
* command output could be parsed as story if not suppressed

Gap Chunk E makes those risks explicit.

⸻

1. Migration and command doctrine

The doctrine is:

Old data is evidence, not canon.
Commands inspect unless explicitly manual.
ReleaseCheck must fail loudly when safety is missing.
Migration repairs structure, not story truth.
Quarantine beats guessing.

No old state, old Story Card, old command output, debug text, or help text may create gameplay truth.

Migration is allowed to repair schema shape and preserve clearly valid data.

Migration is not allowed to invent items, quests, actors, abilities, XP, or rewards from old prose.

3. Migration authority

Migration may be triggered only by:

StateManager.migrate
/migration command inspection
explicit safe migration pass during initialization

Migration may not be triggered by:

* Story Card text
* Context text
* normal parser hits
* generated card content
* old help/debug output
* normal AI output unless it is an explicit migration command, which MVP should not support as gameplay text

⸻

4. Migration source types

Migration must treat sources differently.

4.1 State object data

Old structured state data may be imported if:

* field is recognized
* type is safe or repairable
* value passes sanitizer/validator
* source does not contradict newer state
* import does not duplicate records

4.2 Old Story Cards

Old Story Cards are not canon.

They may be:

* detected
* matched to protected card definitions
* quarantined
* ignored
* marked for manual review
* used for duplicate detection

But card prose may not directly create gameplay state.

4.3 Old debug/audit logs

Old logs are not canon.

They may be archived, compressed, or ignored.

They must not generate events.

4.4 Old command/help text

Old command/help output is not canon.

It must not be parsed into state.

4.5 Old player setup text

Old setup text may be considered only through Startup Setup Import rules.

If gameplay already started, setup import is locked unless manual override exists.

6. Migration idempotency

Migration must be safe to run more than once.

Required rule:

Running migration twice must not duplicate imported records, protected cards, items, quests, actors, abilities, XP, rewards, or warnings beyond capped audit records.

6.1 Migration operation keys

Every meaningful migration action needs a stable operation key.

Examples:

migration.init.schema_v1
migration.import.player.name
migration.repair.body.ep.default
migration.quarantine.card.old_inventory_crown
migration.neutralize.duplicate.protected.player_sheet.card_002
migration.ignore.old_debug_log.block_7

6.2 Permanent migration keys

These should not expire:

* schema migration completed
* protected card duplicate neutralization
* old generated card tombstone
* player identity import
* starting inventory import
* reward migration

6.3 Idempotency tests

Migration must pass:

* run once produces expected repair records
* run twice produces no duplicate state
* run twice does not create duplicate cards
* run twice does not add duplicate warnings beyond capped audit

7. Safe import rules

7.1 Player state import

Safe to import from old structured state if:

* name is valid and not generic/junk
* race/species is valid text
* age is valid text or number
* appearance is valid text
* level is safe positive number
* stats are safe positive numbers
* build identity is valid text

Must not import from old Story Card prose unless manual review confirms.

7.2 Body state import

Safe to import:

* HP/MP/EP current/max if numeric and sane
* injuries if structured and sanitized
* conditions if structured and sanitized
* fatigue if known enum
* deathBoundary if known enum

Repair if:

* EP missing: add default
* current > max: clamp current to max and audit
* negative resource: clamp to 0 and audit
* unknown fatigue: quarantine or default to normal with warning

7.3 Inventory import

Safe to import structured items if:

* item name passes sanitizer
* item has owner/custody/access or can be safely defaulted
* quantity is positive
* duplicate canonical key is handled
* sold/destroyed/consumed/lost states preserved

Do not import inventory from card prose.

Quarantine if:

* item name is junk
* item has impossible state
* item duplicates unique item without clear merge
* item appears only in old card text

7.4 Ability import

Safe to import structured abilities if:

* name passes ability name policy
* status is known
* candidate/stable distinction exists or can be safely inferred
* cost label is known or unknown
* evidence is structured or omitted safely

If status unclear:

import as candidate or quarantine, not stable

Do not import stable ability from old card prose alone.

7.5 Quest import

Safe to import structured quests if:

* title is valid or can be generated safely
* status is known or mapped
* objectives are structured
* rewards are separated into promised/ready/paid
* reward keys are not duplicated

If old quest says reward was paid but ledger missing:

* quarantine payment status or mark disputed
* do not add currency from old text

7.6 Actor import

Safe to import structured actors if:

* name passes actor name policy
* importance is known or inferred conservatively
* presence is known or default unknown
* status is known or default unknown
* memories have truthStatus or default claimed/unknown

Do not import random old scene actors as persistent actors unless important.

7.7 Place import

Safe to import structured places if:

* name passes place name policy
* current location can be identified
* generic scene-only locations are not promoted

If old current location is unclear:

* keep currentLocation confidence unknown/likely
* do not create many place cards

⸻

8. Quarantine rules

Quarantine is used when data might matter but is unsafe to import.

8.1 Quarantine instead of guessing

Quarantine if:

* source is old card prose
* field type is wrong but possibly meaningful
* item/actor/place/ability name fails sanitizer
* reward/payment status is contradictory
* player identity conflicts
* duplicate unique record exists
* old state references missing IDs
* old generated card has broad trigger
* old quest status cannot be mapped

8.2 Quarantine must be visible

Quarantined records must be inspectable through:

/quarantine
/migration
/stateaudit
/releasecheck

8.3 Quarantine must not affect gameplay

A quarantined item is not inventory.

A quarantined quest is not active.

A quarantined actor is not present.

A quarantined ability is not usable.

A quarantined card does not become canon.

8.4 Quarantine resolution

MVP may not include manual resolution commands.

Later manual tools may resolve quarantined records explicitly.

Until then, quarantine is read-only.

⸻

9. Polluted-save repair rules

A polluted save is a save containing unsafe old state/cards/logs that could contaminate new canon.

9.1 Pollution indicators

* duplicate protected cards
* old generated cards with generic triggers
* old managed card text containing inventory/quest/ability facts
* old malformed state fields
* old patch-layer flags
* old pending candidates with junk names
* old dirty queues with unknown targets
* old debug text stored in gameplay buckets
* old command outputs stored as story facts

9.2 Polluted-save repair actions

Allowed actions:

* repair schema shape
* quarantine unsafe records
* mark duplicate card warning
* tombstone old junk managed card if safe
* clear stale temporary parser candidates
* cap logs
* rebuild protected card registry from state
* set generatedCardsEnabled false
* set CardSync dry-run/safe mode

Forbidden actions:

* import old card prose as gameplay truth
* delete user-created cards blindly
* create missing inventory from old Inventory card
* create missing quest from old Quest card
* create stable ability from old Ability card
* create actor biography from old Social card
* enable generated cards automatically

⸻

10. Old Story Card migration rules

Old cards must be handled by category.

10.1 Old protected card equivalent

Examples:

* old Player Summary
* old Body Status
* old Ability Index
* old Inventory Summary
* old Quest Summary
* old Actor Memory
* old Time/Route Summary

Action:

* detect as old managed/protected-equivalent
* do not import prose
* link only if exact safe singleton match
* otherwise mark duplicate/manual review

10.2 Old generated actor/place/item/ability cards

Action:

* do not import as canon
* check for junk/generic names
* check broad triggers
* quarantine or tombstone if clearly managed junk
* leave user cards alone unless clearly managed and unsafe

10.3 Old card with safe marker but unknown key

Action:

* quarantine/manual review
* do not delete
* do not import

10.4 Old card with broad trigger

Action:

* mark warning
* if managed by old AIDRPG/TASIS and safe mode permits, plan neutralization
* otherwise manual review

10.5 Old card prose examples

Old card says:

Player owns Crown of Dawn.

Result:

* no Crown in inventory
* quarantine card claim
* audit warning

Old card says:

Active Quest: Clear the Mill Wolves.

Result:

* no active quest unless state already has it
* quarantine/manual review

Old card says:

Mara is your companion.

Result:

* no companion status unless state confirms
* possible quarantine claim

⸻

11. Migration conflict handling

11.1 Player identity conflict

If old structured state conflicts with current protected state:

* preserve current newer state
* quarantine old conflicting value
* audit conflict

Example:

current player name = Arin
old card says player name = Joren

Result:

* player remains Arin
* Joren claim quarantined

11.2 Inventory conflict

If two old items appear to be same unique item:

* use resolver/sanitizer
* merge only with high confidence
* otherwise quarantine duplicate

11.3 Quest reward conflict

If old quest says rewardStatus paid but currency does not show payment:

* do not add currency automatically
* mark rewardStatus disputed or quarantine conflict
* require future manual resolution

11.4 Actor presence conflict

If old actor state says Mara present but current scene does not include her:

* preserve current scene truth
* set presence unknown/elsewhere if needed
* quarantine old presence if from card

12. Migration command contract

12.1 /migration

Purpose:

Show migration status.

Must display:

* currentMigrationVersion
* migrationStatus
* imported count
* repaired count
* quarantined count
* ignored count
* neutralized card count
* warnings/errors
* last migration turn

Must not:

* import new data from command output
* perform unsafe repairs unless explicitly designed later
* parse its own output

12.2 /quarantine

Purpose:

Show unsafe legacy data waiting for review.

Must display:

* quarantineId
* source
* preview
* reason
* severity
* suggestedAction
* resolved status

Must not:

* restore quarantined data automatically
* mutate gameplay state

12.3 /cleanup

MVP behavior:

* show cleanup status or run safe lightweight cleanup only if explicitly allowed
* never remove important truth
* audit any destructive action

Default MVP recommendation:

/cleanup is diagnostic only until Cleanup Spec is coded.

12.4 /stateaudit

Shows:

* schema status
* missing field repairs
* integrity warnings
* malformed/quarantined buckets
* state size/budget warnings

Must not mutate gameplay state except diagnostic metadata.

13. ReleaseCheck doctrine

/releasecheck is the script’s truthfulness gate.

It must not say the build is safe unless the required systems exist and pass their checks.

ReleaseCheck must be honest, even if the answer is bad.

It should produce:

PASS
WARN
FAIL
BLOCKED

13.1 PASS

All required checks pass for current build stage.

13.2 WARN

System can run but has known non-blocking risks.

13.3 FAIL

A required safety check failed.

13.4 BLOCKED

A required spec/system/test is missing for a requested feature.

15. /releasecheck exact checks

15.1 Build/version checks

Must verify:

* version exists
* schemaVersion exists
* build stage exists
* MVP/deferred feature flags exist
* generatedCardsEnabled false in MVP

Fail if:

* version missing
* generated cards enabled in MVP
* feature flags missing

15.2 Runtime hook checks

Must verify:

* runtime bucket exists
* valid return behavior defined
* fail-soft handler exists
* input/context/output contracts exist
* command suppression exists
* duplicate output hash exists

Fail if:

* Context can mutate gameplay
* command output can be parsed
* output replay can duplicate consequences

15.3 State schema checks

Must verify required buckets:

player
body
progression
inventory
abilities
quests
actors
places
time
cards
operationLedger
audits
runtime
migration
cleanup

Fail if core bucket missing.

Warn if optional/deferred bucket missing.

15.4 Parser safety checks

Must verify:

* parser hit schema includes all safety flags
* parser cannot mutate state directly
* non-canon source suppression exists
* quote/negation/hypothetical/dream/rumor markers exist
* input is intent only

Fail if:

* visible item can become inventory directly
* parser writes inventory/quests/XP directly
* command/context/card text can be parsed

15.5 Canon validation checks

Must verify:

* CanonValidator exists
* source eligibility rules exist
* confidence thresholds exist
* duplicate check exists
* actor presence check exists
* item custody check exists
* ability status check exists
* quest reward status check exists

Fail if accepted proposals can bypass CanonValidator.

15.6 Reducer ownership checks

Must verify:

* ReducerRegistry exists
* unknown reducer rejected
* each event type has one owner
* reducers do not process unvalidated proposals

Fail if multiple modules can write same truth without owner boundary.

15.7 OperationLedger checks

Must verify buckets:

permanentKeys
recentKeys
rewardKeys
cardKeys
sourceUseKeys

Must verify max recent keys.

Fail if:

* reward keys missing
* duplicate detection missing
* card keys missing while CardSync enabled

15.8 Inventory/custody checks

Must verify access states:

held
equipped
stored
npc_custody
inaccessible
lost
sold

consumed

Fail if:

* visible can be owned
* available_loot can be used before pickup
* npc_custody item can be used
* sold/destroyed/consumed item can be used

15.9 Ability safety checks

Must verify statuses:

unknown
hint
candidate
unstable
stable
sealed
unavailable

Fail if:

* candidate equals stable
* failed attempt creates stable ability
* sealed ability can be used
* candidate ability creates generated card

15.10 Quest/reward checks

Must verify:

* quest statuses exist
* promised/ready/paid/disputed reward states exist
* reward payment uses permanent key

Fail if:

* promised reward adds currency
* objective complete pays automatically
* reward can pay twice

15.11 Actor/place checks

Must verify:

* actor presence states exist
* absent actor actions blocked
* scene-only actors expire
* relation phrase safety exists
* travel intent differs from arrival
* place substring safety exists

Fail if:

* absent companion can act
* head toward changes location
* Old Chapel Road resolves to Old Chapel incorrectly

15.12 Context checks

Must verify:

* ContextBuilder read-only
* packet priority exists
* packet budget exists
* uncertainty labels exist
* context audit exists

Fail if Context mutates gameplay state.

15.13 CardSync checks

Must verify:

* generated cards disabled in MVP
* Card API adapter exists before live writes
* protected singleton map exists
* card text cannot create state
* broad triggers rejected
* write budget exists

Fail if:

* generated cards enabled early
* duplicate protected card creation possible without detection
* live writes enabled without adapter
* card prose can create canon

15.14 Migration/quarantine checks

Must verify:

* migration bucket exists
* quarantine bucket exists
* migration idempotency keys exist
* old card prose not imported as canon
* migration audit exists

Fail if:

* migration can import card prose as inventory/quest/ability
* repeated migration duplicates records

15.15 Cleanup/dirty queue checks

Must verify:

* dirty queue exists
* cleanup is conservative
* cleanup may never remove important truth
* cleanup audit exists

Fail if cleanup can delete active inventory, active quests, important actors, permanent keys, reward keys, or protected registry.

15.16 Testing gate checks

Must verify whether tests have passed:

* MVP Gate 1
* MVP Gate 2
* MVP Gate 3
* MVP Gate 4
* MVP Gate 5
* MVP Gate 6
* MVP Gate 7
* MVP Gate 8
* Gap tests A/B/C/D/E as applicable

Fail if build stage claims complete without required tests.

15.17 Deferred system checks

Must verify these remain disabled in MVP:

* economy
* crafting
* investigation
* reputation/factions
* domain/labor
* absorption/evolution
* generated cards
* multi-protagonist
* advanced combat/warfare

Fail if any active without mini-spec and build unlock.

17. Command honesty doctrine

Commands are a user-facing contract.

They must not exaggerate.

They must not hide disabled systems.

They must not mutate gameplay unless explicitly manual and audited.

MVP command rule:

Commands inspect. Commands do not play the game for the player.

19. Disabled/deferred command behavior

If a command references a disabled system, respond honestly.

19.1 Economy commands

Example:

/shop
/buy
/sell
/economy

MVP response:

Economy is not active in MVP. Simple currency display may exist, but full buying/selling requires Economy Mini-Spec and a later build phase.

19.2 Crafting commands

Example:

/craft
/recipes
/materials

MVP response:

Crafting is not active in MVP. Materials may appear as inventory items, but crafting projects require Crafting Mini-Spec.

19.3 Investigation commands

Example:

/cases
/clues
/evidence

MVP response:

Investigation is not active in MVP. Claims may be stored as actor/quest notes, but cases and evidence require Investigation Mini-Spec.

19.4 Domain/labor commands

Example:

/domain
/workers
/projects

MVP response:

Domain and labor systems are not active in MVP. They require Domain/Labor Mini-Spec.

19.5 Absorption/evolution commands

Example:

/absorb
/evolve
/devour

MVP response:

Absorption and evolution are not active in MVP. Attempts may be treated narratively, but mechanical gains require Absorption/Evolution Mini-Spec.

19.6 Generated CardSync commands

Example:

/cardsync live on
/generatecards

MVP response:

Generated cards are disabled in MVP. Protected card dry-run/audit may exist, but generated CardSync requires beta unlock and tests.

AIDRPG Core MVP v0.1
Schema Version: 1
Build Stage: pre-code / phase 1 / phase 2 etc.
Generated Cards: disabled
CardSync: dry-run/safe/live protected as applicable
Deferred Systems: economy, crafting, investigation, domain, absorption, generated cards
Last Migration: status
ReleaseCheck: last result if available

This command must not mutate gameplay state.

26. Audit output style rules

Audit output should be readable, not raw schema dumps.

26.1 Good audit style

Rejected item pickup: "jeweled cup" was hypothetical, not acquired.
Skipped reward payment: duplicate reward key already used.
Suppressed generated card: generated cards are disabled in MVP.

26.2 Bad audit style

ValidationResult[0].p.flags.negated == true therefore p.f.write=false

Raw details may appear in debug mode, but normal diagnostics should be readable.

⸻

29. Final Gap Chunk E doctrine

Migration must not be brave.

It must be careful.

Commands must not be impressive.

They must be honest.

ReleaseCheck must not flatter the build.

It must protect the player from false confidence.

The final rule is:

When old data is unsafe, quarantine it.
When a system is disabled, say so.
When a check fails, fail loudly.
When a command prints state, do not parse it as story.
When a card says something, do not treat it as canon.
