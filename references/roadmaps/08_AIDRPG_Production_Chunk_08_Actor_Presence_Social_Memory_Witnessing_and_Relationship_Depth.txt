# AIDRPG Production Chunk 08 — Actor Presence, Social Memory, Witnessing, and Relationship Depth

## 0. Document status

**Document name:** AIDRPG Production Chunk 08 — Actor Presence, Social Memory, Witnessing, and Relationship Depth  
**Production sequence:** 08 of 25 remaining production chunks  
**Build target:** WorldLedger V0.17.7 quest/reward-depth accepted build / AIDRPG Core MVP expansion path  
**Purpose:** Deepen actor records, actor presence, scene-only actors, reference-only actors, absent actors, witness memory, direct-informed memory, relationship evidence, and social continuity without false presence, duplicate actors, or unsafe reputation automation.  
**Status:** Core gameplay-depth production chunk.  
**Follows:** Production Chunk 07 — Quest, Objective, Reward, and Promise/Payment Depth.  
**This document does not contain final script code.**

Production Chunk 08 exists because actors are where AI Dungeon continuity can either feel alive or become badly corrupted. Old rough attempts showed the same risks repeatedly: duplicate actors from titles/names, absent actors treated as present, reference-only names treated as scene participants, private witness memory becoming global reputation, generic guards becoming permanent major NPCs, command/card/context text creating memories, and actor harm being applied to a statue, painting, title, or training dummy named after someone.

This chunk turns actors into structured, useful, bounded state. The goal is not full reputation, faction, romance, party, summon, or NPC combat automation yet. The goal is reliable actor presence, source-bound memory, and relationship evidence that future systems can safely build on.

---

# 1. Chunk doctrine

```text
Mentioned is not present.
Absent is not present.
Reference-only is not present.
Generic is not automatically persistent.
Witnessed is not global reputation.
Private is not public.
Relationship claim is evidence, not absolute truth.
Actor memory requires presence or direct information.
A training dummy named after Mira is not Mira.
```

Actor truth must be local, source-aware, duplicate-safe, scene-aware, and AI-Dungeon-safe.

---

# 2. Why this chunk comes now

Production Chunk 07 made quest givers, reward payers, turn-ins, and quest references safer. Actors come next because they connect to quest givers, reward payers, witnesses, companions, enemies, merchants, trainers, faction contacts, social memory, relationship changes, scene presence, future reputation, future party/summon logic, and world persistence.

If actors are not safe now, later systems will create false witnesses, false public knowledge, duplicate NPCs, and broken relationship state.


Rules:

```text

key does not contain full raw output
key does not come from command/card/context text

bad compound/connectors are cleaned without creating fake actors
```

Named/important actors may become persistent. Generic actors normally become scene actors.

Examples:

```text

High Priestess Ilyra -> persistent actor

A guard -> scene actor by default
A merchant -> scene actor by default
Three bandits -> scene group actor by default
```

# 14. Actor CanonValidator expansion

Accept present actor only when safe story output places actor in the current scene or direct interaction, actor target is bound, and source is not absent/reference-only/object/statue/painting/dummy/title/dream-only/command/context/card/audit/debug.

Accept scene-only actor when a generic actor or group appears in scene and should not be persistent by default.

Accept absent/reference-only actor when source explicitly says actor is absent/elsewhere/not present, or actor is used only as comparison/title/reference/object label.

Accept memory only when actor is present and directly witnesses event, or actor is directly informed. Reject memory when actor is absent, reference-only, only rumored, not informed, or source is command/card/context/audit/debug.

# 19. Witness memory rules

Present witness example:

```text
The Veteran Guard watches you steal the apple.
```

Expected: Veteran Guard gets witnessed_action memory, private/local scope, no global reputation.

Absent actor example:

```text
Mira is not here when you steal the apple.
```

Expected: Mira receives no witness memory.

Directly informed example:

```text
You tell Mira that you stole the apple.
```

Expected: Mira gets heard_report/direct_conversation memory only if present/directly addressed or output confirms contact.

Public group example:

```text
The whole market sees you steal the apple.
```

Expected: scene/public_local memory candidate; reputation/faction numeric automation remains deferred.
