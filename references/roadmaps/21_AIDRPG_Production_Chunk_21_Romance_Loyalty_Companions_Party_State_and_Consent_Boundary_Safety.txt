# AIDRPG Production Chunk 21 — Romance, Loyalty, Companions, Party State, and Consent/Boundary Safety

## 0. Document status

**Document name:** AIDRPG Production Chunk 21 — Romance, Loyalty, Companions, Party State, and Consent/Boundary Safety  
**Production sequence:** 21 of 25 production chunks  
**Build target:** WorldLedger V0.17.20 factions/reputation/law accepted build / AIDRPG Core MVP expansion path  
**Purpose:** Add relationship evidence, romance boundaries, companion recruitment, party presence, loyalty evidence, companion autonomy, consent/boundary records, party display, and safe relationship progression without forced romance, private-to-public drift, mind-control consent bugs, command/card/context relationship canon, or companion state corruption.  
**Status:** Core gameplay-depth production chunk.  
**Follows:** Production Chunk 20 — Factions, Reputation Evidence, Law, Crime, and Consequence Boundaries.  
**This document does not contain final script code.**

Production Chunk 21 exists because companion and romance systems are emotionally important, mechanically useful, and very easy to corrupt.

AI Dungeon gameplay benefits when companions remember the player, react to events, travel with the party, disagree, protect, leave, forgive, distrust, develop bonds, and participate in quests.

But old or rough systems often break this by doing one of these:

```text
one friendly line becomes romance
one flirt becomes consent to everything
private affection becomes public reputation
NPC follows once and becomes permanent party member
quest escort becomes loyal companion
mind control/charm becomes real consent
threat/coercion becomes romance progress
relationship card text overwrites relationship truth
context says companion is present, so they teleport into scene
command output says Mira trusts player, so trust becomes canon
party display gets parsed back into state
cleanup deletes companion boundaries or active party state
companion loyalty becomes obedience with no autonomy
companion inventory/custody merges into player inventory
```

Chunk 21 prevents those failures.

The goal is to make relationships and companions feel alive while preserving agency, consent, autonomy, source routing, and AI Dungeon story flexibility.

---

# 1. Chunk doctrine

```text
Friendliness is not romance.
Romance interest is not consent.
Consent is event-specific and revocable.
Loyalty is not obedience.
Companion is not property.
Escort target is not party member.
Following is not permanent recruitment.
Private affection is not public reputation.
Charm, coercion, fear, intoxication, confusion, or mind control is not valid consent.
Command text is not relationship truth.
Card text is not relationship truth.
Context text is not relationship truth.
```

Relationships should grow from evidence.

Party state should grow from validated recruitment and presence.

Boundaries should be protected before romance, loyalty, or party mechanics can matter.

---

# 2. Why this chunk comes now

Production Chunk 20 added factions, law, crime, public/private consequence boundaries, witnesses, and reputation evidence.

Companions and romance come after that because they need:

```text
actor identity and presence from PC08
private/public memory from PC08 and PC20
quest and reward boundaries from PC07
inventory/custody boundaries from PC05
place/time scene presence from PC09
combat event boundaries from PC12
form/social visibility boundaries from PC13
faction/reputation boundaries from PC20
context/card non-canon safety from PC16
```

If relationship and party systems are not bounded now, later companion quests, summons, pets, mounts, domain NPCs, and advanced combat party systems will inherit unsafe assumptions.

# 5. Relationship state model

Relationships need a stable state area.

Recommended shape:

```text
relationships: {
  profiles: {},
  evidence: {},
  romanceStates: {},
  consentBoundaries: {},
  consentEvents: {},
  boundaryViolations: {},
  loyaltyEvidence: {},
  trustStates: {},
  sharedHistory: {},
  warnings: [],
  notes: []
}
```

Party/companions should be separate:

```text
companions: {
  records: {},
  recruitments: {},
  partyMembers: {},
  presence: {},
  roles: {},
  autonomy: {},
  conflicts: {},
  questHooks: {},
  warnings: [],
  notes: []
}
```

Do not hide party state inside actor notes only.

Do not treat relationship score as a single absolute truth.

Evidence matters.

# 24. Relationship CanonValidator expansion

CanonValidator must enforce relationship safety.

## 24.1 Accept relationship evidence when

```text
safe output/input shows clear interaction between player and actor
actor target is bound
source is not command/context/card/audit/debug
not dream/rumor/metaphor only
not coercion misread as affection
operation key not duplicate
```

Result:

```text
relationship evidence record
possible trust/relationship summary update
no automatic romance/consent/party mutation unless event type validates
```

## 24.2 Accept romance interest when

```text
safe output shows clear non-coerced romantic interest signal
actor target is bound
no active refusal/boundary conflict
not command/card/context source
```

Result:

```text
romance evidence / possible interest update
not broad consent
```

## 24.3 Accept consent/boundary event when

```text
safe output shows clear consent, refusal, withdrawal, or boundary statement
scope is captured
invalidating conditions are checked
```

Result:

```text
ConsentEventRecord / ConsentBoundaryRecord
relationship state constrained accordingly
```

## 24.4 Reject romance/consent advancement when

Any are true:

```text
coercion/threat/fear
mind control/charm/possession
confusion/intoxication/unsafe state
ambiguous age/age-uncertain context
active refusal or boundary not resolved
command/context/card source
dream/vision/rumor/quote only
```

```text

```

```text

```
