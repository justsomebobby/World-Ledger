# AIDRPG Production Chunk 16 — Context Builder Budget, Memory Priority, and Card Sync Safety

## 0. Document status

**Document name:** AIDRPG Production Chunk 16 — Context Builder Budget, Memory Priority, and Card Sync Safety  
**Production sequence:** 16 of 25 remaining production chunks  
**Build target:** WorldLedger V0.17.15 world-bible/lore-boundaries accepted build / AIDRPG Core MVP expansion path  
**Purpose:** Deepen context packet construction, token/character budgeting, memory priority, source blocking, stale-context prevention, safe summaries, dry-run Card Sync, protected card boundaries, and context/card non-canon safety without losing gameplay-critical state or re-importing generated summaries as truth.  
**Status:** Core infrastructure production chunk.  
**Follows:** Production Chunk 15 — World Bible Import, Lore Authority, and Knowledge Boundaries.  
**This document does not contain final script code.**

Production Chunk 16 exists because AI Dungeon scripting succeeds or fails on context. A perfect ledger still fails if the prompt sends stale facts, hidden lore, false ownership, unpaid rewards as paid rewards, candidates as confirmed powers, or card mirror text as canon. This chunk makes context and card handling safe, prioritized, compact, source-aware, and useful for real gameplay.

---

# 1. Chunk doctrine

```text
Context is guidance, not evidence.
Command output is guidance, not evidence.
Card mirror output is guidance, not evidence.
Generated summaries are guidance, not evidence.
Stale context must never beat current ledger truth.
Hidden lore must not leak into normal context.
Candidate state must not be worded as confirmed state.
Dry-run Card Sync is not live Card Sync.
Card writes must be protected, gated, audited, and reversible before activation.
```

Context should help the model remember the right things. It must not become another source of false canon.

---

# 2. Why this chunk comes now

Production Chunk 15 separated world fact, player knowledge, hidden lore, Story Card lore, and context non-canon behavior. Context and Card Sync safety come next because every previous system needs a reliable way to talk to AI Dungeon:

```text
player identity and body
inventory/equipment
abilities
quests/rewards
actors/social memory
place/time/deadlines
progression/stats
combat state
form/race constraints
threat/encounter danger
world lore/player knowledge
```

If context is not budgeted and prioritized now, later systems will add too much information and break coherence.

# 20. Context priority order

Recommended critical order:

```text
1. system safety boundaries / source-blocking warnings when needed
2. player identity and true/current form/body constraints
3. current location/current scene/time/deadlines
4. active combat/damage/death-boundary critical status
5. active encounter/threat warning
6. active quest objective and unpaid/paid reward truth
7. active injuries/conditions/resources
8. immediately present actors/witnesses
9. owned/equipped critical inventory and visible/custody distinctions
10. stable abilities and important candidates/failures
11. relevant player-known lore
12. recent important history
13. low-priority background lore
14. debug/audit omitted from normal context
```

Identity/form/current scene should not be pushed out by background lore.

# 21. Section wording safety rules

Required wording examples:

```text
Candidate ability: Ember Ward is being trained, not stable.
Visible item: A silver ring is visible nearby, not owned.
Custody: Mira holds the Crown of Dawn; it is not yours.
Reward: Old Bren promised 15 gold; it has not been paid.
Quest: Clear the Mill Wolves is active; objective incomplete.
Form: You are physically in wolf form; true race remains Human.
Lore: Local rumor says wolves fear silver bells; unconfirmed.
Hidden lore: omitted.
```

Forbidden unless truly confirmed:

```text
You know Ember Ward.
You have the silver ring.
You own the Crown.
Old Bren paid 15 gold.
The wolves fear silver bells.
You are a wolf species now.
The hidden bell controls the wolves.
```

# 22. ContextBuilder behavior

ContextBuilder should:

```text
read owner state only
request section renderers
filter by source/knowledge boundaries
score priority
fit sections to budget
compress low-priority safe sections
label uncertainty
omit hidden/blocked/debug content
emit ContextPacketRecord
mark output as non-canon source
```

ContextBuilder should not mutate owner state, infer missing owner state, promote candidate facts, reveal hidden lore, write cards live, or create memories as gameplay events.

---

# 23. ContextBudgetManager behavior

Budget manager should:

```text
reserve critical budget
calculate approximate char/token cost
include critical sections first
summarize or omit low-priority sections
record omitted reasons
warn when critical sections are too large
never fill budget with hidden/unsafe content
```

Fallback order:

```text
omit debug
omit stale low-priority summaries
omit irrelevant lore
compress old history
compress actors/inventory to current scene essentials
preserve current identity/body/location/quest/combat warnings
```

---

# 24. MemoryPriorityManager behavior

MemoryPriorityManager should promote active/current/critical facts and lower old/resolved/background facts. It must keep protected identity, form, active quest, deadline, danger, and severe body facts visible when relevant.

It must not prioritize background lore over current state, keep resolved wounds as active injuries, keep old locations after movement, or hide active deadlines because lore is long.

# 31. Command updates

## `/context`

Shows context packet preview, included sections, omitted sections with reasons, budget used, hidden lore filtering, and non-canon warning.

## `/memory`

Shows priority facts, active/current memories, summarized old facts, blocked/stale memory warnings.

## `/cardaudit`

Shows Card Sync mode dry-run, protected cards, proposed mirrors, blocked write risks, and confirmation that no live writes occurred.

## `/stateaudit`

Shows context/source-blocking policy status, stale context checks, memory priority warnings, and card sync safety status.

All command output starts with `[AIDRPG]` and remains non-canon.

# 32. Good and bad context examples

Good:

```text
Player: True race Human; currently physically in wolf form. No human hands, quadruped movement, altered speech.
Location: Market Lane, crowded street near the old fountain.
Quest: Clear the Mill Wolves is active; Old Bren promised 15 gold, not paid.
Inventory: You carry a red healing potion. Mira holds the Crown of Dawn; it is not yours.
Ability: Ember Ward is a candidate under training, not stable.
Lore: Local rumor says wolves fear silver bells; unconfirmed. Hidden wolf-bell truth is not known.
```

Bad:

```text
You are a wolf species. You own the Crown. Old Bren paid you 15 gold. You know Ember Ward. Wolves fear silver bells. You are in the Chapel.
```

Bad because it promotes or overwrites current form into species, custody into ownership, promise into payment, candidate into stable, rumor/hidden lore into fact, and wrong location into current state.
