# AIDRPG Script Build Roadmap v1.1 — Gap-Aligned Current Build Plan

## 0. Document status

**Document name:** AIDRPG Script Build Roadmap v1.1 — Gap-Aligned Current Build Plan  
**Purpose:** Update the original Script Build Roadmap v1 so it explicitly incorporates Gap Closure Addendum v1 and Gap Chunks A–G.  
**Status:** Current build-roadmap authority after v1.2 package.  
**This document does not contain final script code.**

This document answers the user's question:

> How do the Gap Chunks A–G affect the chunk plan?

The answer is:

The original 34 Build Chunks are still valid, but they are now controlled by a stronger pre-code safety gate. Gap Chunks A–G do not replace the build roadmap. They modify it by adding exact safety rules that every build chunk must obey.

The old roadmap said:

```text
Create Build Chunk 1, then continue through Build Chunk 34.
```

The corrected roadmap now says:

```text
Gap Chunks A–G must be treated as completed pre-code authority.
Then Build Chunks 1–34 proceed under those rules.
Every Build Chunk must cite and obey the relevant Gap Chunk rules.
```

# 1. What changed after Gap Chunks A–G

## 1.1 The build has a new pre-code gate

Before coding starts, the build now requires the following safety documents to exist and control implementation:

```text
Gap Chunk A — Old Fix Salvage Matrix
Gap Chunk B — Runtime and Hook Contract Spec
Gap Chunk C — Story Card API Adapter and Protected Singleton Contract
Gap Chunk D — Parser Rulebook, Resolver, and Name/Trigger Policy
Gap Chunk E — Migration, ReleaseCheck, and Command Honesty Spec
Gap Chunk F — Context, Dirty Queue, Cleanup, and Performance Spec
Gap Chunk G — Startup, Identity Drift, and Natural Confirmation Spec
```

These are no longer optional.

They are now the safety layer between the design bible and the first code attempt.

## 1.2 The original roadmap was not wrong

The original Build Roadmap v1 was a correct practical chunk plan.

What it lacked was exact old-fix preservation and blocker mapping.

Gap Chunks A–G close that missing layer.

Therefore:

```text
Roadmap v1 = correct build order.
Gap Chunks A–G = exact safety controls.
Roadmap v1.1 = build order plus safety controls.
```

## 1.3 Build Chunk 1 is still the next action

Because Gap Chunks A–G are now created, the next chunk remains:

```text
Build Chunk 1 — Implementation Start Packet
```

But Build Chunk 1 must now include the gap-closure authority stack and must not begin coding blindly.

# 5. How Gap Chunks A–G affect each Build Chunk

## Build Chunk 1 — Implementation Start Packet

### Original purpose

Create the first coding handoff packet.

### v1.1 adjustment

This chunk must now begin by declaring:

```text
Gap Chunks A–G are complete and authoritative.
No code may ignore them.
```

It must define Script v0.1 as:

```text
A safety-first MVP foundation, not the full final RPG engine.
```

### Relevant Gap Chunks

- A: old fixes must be preserved as owner rules/tests
- B: runtime contract controls hook behavior
- C: cards mirror state only
- D: parser is conservative
- E: releasecheck/commands must be honest
- F: context/cleanup/performance must be bounded
- G: startup/identity/handoff must be protected

### New blocker language

Build Chunk 1 must say:

```text
If a requested code behavior conflicts with Gap Chunk A–G, do not code it.
If a feature lacks a mini-spec, mark it deferred.
```
