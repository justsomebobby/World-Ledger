AIDRPG Build Chunk 9 — EventScannerLite Parser Shell Plan

0. Document status

Document name: AIDRPG Build Chunk 9 — EventScannerLite Parser Shell Plan
Build target: AIDRPG Core MVP v0.1
Purpose: Define the exact safe parser shell, parser source rules, parser hit schema, safety-flag detection, family boundaries, and parser tests before parser code is generated.
Status: Practical build document.
Follows: Build Chunk 8 — CommandRouter and Command Renderer Implementation Plan.
This document does not contain final script code.

This chunk is useful because the parser is where many old bugs begin.

If the parser is too aggressive, visible items become inventory, promises become payments, rumors become facts, failed abilities become stable abilities, and dreams become canon.

If the parser mutates state directly, CanonValidator and reducers become useless.

If the parser scans commands, context, cards, or audit text, the script corrupts itself.

Build Chunk 9 locks the parser as a safe detector only.

⸻

1. Parser shell doctrine

The parser doctrine is:

The parser detects possible events.
The parser does not create truth.
The parser does not mutate gameplay state.
The parser does not decide canon.
The parser does not bypass validation.

The parser output is a ParserHit.

A ParserHit is not an accepted event.

A ParserHit is only evidence that later systems may turn into an EventProposal.

⸻

2. Why this chunk is a shell, not full parser automation

Build Chunk 9 should not activate the full game parser all at once.

The first parser implementation should be conservative and structurally correct.

It should prove:

* source suppression works
* command output is ignored
* context/card/debug text is ignored
* safety flags are detected
* input is intent only
* output can produce candidate hits
* parser hits have the right shape
* parser hits do not mutate state
* parser output is capped and auditable

Full event interpretation belongs to later proposal, validator, and reducer chunks.

⸻

3. Placement in final script

EventScannerLite belongs in:

Section 12 — Event Scanner Lite Shell

It depends on:

Constants
Utils
Runtime read-only suppression status
AuditLogger for debug/proposal-shell audit if needed

It must not depend on:

ReducerRegistry
InventoryReducer
QuestReducerLite
AbilityReducer
ProgressionReducerLite
CardSyncLite
ContextBuilderLite mutation
StateManager gameplay repair

EventScannerLite may read state lightly for source suppression or current parser mode, but should avoid heavy world scans.

⸻

4. Parser responsibilities

EventScannerLite owns:

* deciding whether a text source is eligible to scan
* splitting current text into safe windows/clauses
* detecting safety flags
* detecting broad event-family hints
* emitting ParserHit records
* capping parser hits
* recording parser shell audit if useful

EventScannerLite does not own:

* creating EventProposal objects
* resolving exact canonical targets
* validating events
* mutating inventory
* mutating abilities
* mutating quests
* mutating actors
* mutating places
* mutating time
* awarding XP
* paying rewards
* creating Story Cards

⸻

6. Parser source authority

Parser must respect source authority.

Allowed scan sources in MVP shell:

input
output

Disallowed scan sources:

command_output
context
story_card
protected_card
generated_card
debug
audit
help
releasecheck
migration_log
old_log
archive
unknown_noncanon

6.1 Input source rule

Input can create intent/attempt hits only.

Input must not create completed success hits.

Example:

I take the sword.

Input hit may be:

item_take_attempt
completedAction = false
attemptOnly = true

Input must not add sword to inventory.

6.2 Output source rule

Output can create possible completed consequence hits if wording is clear and safe.

Example:

You pick up the sword.

Output hit may be:

inventory.item_pickup
completedAction = true

But the parser still does not commit.

6.3 Command output rule

Command output is never a gameplay source.

Any text beginning with:

[AIDRPG]

should be treated as non-canon diagnostic/command text unless explicitly proven otherwise by the hook contract.

7. SourceInfo schema

Parser source checks should use a source info object when possible.

SourceInfo {
  sourceHook: 'input' | 'output' | 'context' | 'command' | 'manual' | 'migration' | 'setup' | 'system' | 'unknown',
  textHash: string,
  isCommandOutput: boolean,
  isContextText: boolean,
  isCardText: boolean,
  isAuditText: boolean,
  isDebugText: boolean,
  isHelpText: boolean,
  scanAllowed: boolean,
  reason: string
}

For early v0.1, the sourceInfo may be simple, but the distinction must be planned.

⸻

8. ParserHit schema

Every parser hit must use the universal ParserHit schema from Gap Chunk D.

ParserHit {
  hitId: string,
  sourceHook: 'input' | 'output' | 'manual' | 'migration' | 'setup',
  rawText: string,
  normalizedText: string,
  matchedText: string,
  eventFamily: string,
  eventType: string,
  subjectText: string,
  objectText: string,
  actorText: string,
  itemText: string,
  placeText: string,
  questText: string,
  abilityText: string,
  completedAction: boolean,
  attemptOnly: boolean,
  negated: boolean,
  hypothetical: boolean,
  quotedSpeech: boolean,
  dreamOrVision: boolean,
  rumorOrClaim: boolean,
  failedOrRevoked: boolean,
  conditional: boolean,
  futureIntent: boolean,
  confidence: number,
  truthStatus: string,
  evidenceType: string,
  parserNotes: string[]
}

8.1 Required safe defaults

If a field is unknown, use safe defaults:

completedAction = false
attemptOnly = true if sourceHook is input or wording is unclear
negated = false unless detected
hypothetical = false unless detected
quotedSpeech = false unless detected
dreamOrVision = false unless detected
rumorOrClaim = false unless detected
failedOrRevoked = false unless detected
conditional = false unless detected
futureIntent = false unless detected
confidence = low/moderate, not high by default
truthStatus = 'unknown' or 'observed' depending family
evidenceType = 'parser_shell'
parserNotes = []

8.2 Hit ID rule

Hit IDs should be stable enough for audit, not random-only.

Recommended pattern:

hit.<sourceHook>.<eventFamily>.<hash(windowText)>.<index>

9. Text normalization rules

Parser normalization should be safe and meaning-preserving.

9.1 Normalize for matching

Allowed:

* convert to safe string
* trim leading/trailing whitespace
* collapse repeated whitespace
* create lowercase matching copy
* normalize curly quotes to plain quotes for quote detection

9.2 Do not strip safety words

Never remove or ignore safety words like:

not
never
no
don't
didn't
can't
failed
almost
could
might
would
if
unless
dream
vision
rumor
says
claims
will
later

These words often decide whether a hit is safe.

9.3 Raw text preservation

Every hit must keep a raw/matched text preview for audit.

Do not store huge full output text in every hit.

Use window text and short previews.

⸻

10. Window splitting rules

Parser should scan current input/output text in windows, not the whole campaign history.

10.1 Window sources

Windows may be:

* sentences
* clauses
* short line segments
* command-free text chunks

10.2 Why windows matter

Output:

You reach for the sword, but Mara stops you. The dagger falls to the ground.

The parser should not treat the whole paragraph as a successful sword pickup.

Each candidate should be considered in its clause/window.

10.3 MVP window limit

Recommended early limits:

maxInputTextLengthToParse = 3000 characters
maxOutputTextLengthToParse = 5000 characters
maxWindows = 30
maxWindowLength = 500 characters

If exceeded:

* scan first safe windows or highest relevance windows
* audit skip if needed
* do not crash

28. Confidence defaults

Parser confidence is preliminary.

Suggested initial confidence:

clear output completed action = 0.70 to 0.75
player input intent = 0.45 to 0.55
quoted speech = 0.25 to 0.35
rumor = 0.20 to 0.30
hypothetical = 0.15 to 0.25
dream/vision = 0.15 to 0.25
negated success = 0.05
command/context/card/audit source = 0.00 and scan rejected

28.1 Confidence cannot override flags

A hit with strong words but bad safety flags must not become canon later.

Example:

In a dream, you receive the Crown of Dawn.

Even though the phrase says receive, dream flag blocks real acquisition.

⸻

29. Parser output caps

Recommended caps:

maxInputParserHits = 10
maxOutputParserHits = 20
maxWindows = 30
maxHitPreviewLength = 160
maxParserAuditLines = 10 per turn

If caps are exceeded:

* keep higher-confidence/high-safety hits first if cheap
* otherwise keep first hits and audit skip
* do not crash
* do not scan entire history to compensate

⸻

30. Parser audit summary

Parser audit should be compact.

Possible summary:

Parser shell scanned output: 4 windows, 2 hits, 1 skipped by command/context suppression.

Possible hit summary:

Parser hit: item_pickup_candidate from output, matched "pick up the rusty dagger", completedAction=true.

Do not store huge full text.

⸻

31. Parser and Runtime relationship

Runtime decides when parser may run.

Parser must only run after Runtime confirms:

* source is Output hook or Input intent shell
* command output suppression did not trigger
* duplicate output replay did not trigger
* text is not [AIDRPG] diagnostic output
* parser feature/shell mode allows scanning

Parser should still have its own non-canon source rejection as a backup.

⸻

32. Parser and CommandRouter relationship

CommandRouter handles commands in Input hook.

Parser must not parse command text.

Input:

/inventory

must never produce item hits.

Command output beginning with [AIDRPG] must never produce hits.

⸻

33. Parser and ProposalBuilder relationship

Parser produces ParserHits.

ProposalBuilder later converts ParserHits to EventProposals.

Forbidden path:

ParserHit -> Reducer

Allowed path:

ParserHit -> ProposalBuilder -> CanonValidator -> ReducerRegistry -> OwnerReducer

Build Chunk 9 stops at ParserHit.

⸻

34. Parser and AuditLogger relationship

Parser may call AuditLogger for summary/debug only.

Parser audit must not become gameplay source.

Parser should not over-audit every tiny hit forever.

Use caps.

⸻

35. Parser and StateManager relationship

Parser assumes StateManager already initialized state.

Parser must not repair state.

Parser must not use StateManager as a hidden mutation path.

If parser detects malformed state dependency, it should return no hits and audit warning, not repair gameplay.

⸻

36. Parser and Story Cards

Parser must not scan Story Card text.

Parser must not scan protected card text.

Parser must not scan generated card text.

Parser must not create Story Cards.

Generated cards remain disabled.

⸻

37. Early v0.1 activation level

For Core MVP v0.1 foundation, parser can be in one of two acceptable modes.

37.1 Inert shell mode

EventScannerLite exists but returns no hits.

It reports:

Parser shell present; full scanning disabled.

This is acceptable only before parser tests are needed.

37.2 Safe hit shell mode

EventScannerLite detects safety flags and a limited set of family hints, returning ParserHits.

It still does not create proposals or mutate state.

Preferred for Build Chunk 9 implementation.

⸻

38. Parser releasecheck requirements

ReleaseCheck must verify:

* parser exists or is honestly marked shell-only
* parser cannot mutate state directly
* parser source suppression exists
* command output cannot be parsed
* context/card/audit/help text cannot be parsed
* ParserHit schema includes safety flags
* input parser produces intent/attempt only
* output parser gated by Runtime duplicate/suppression checks
* parser hit caps exist

ReleaseCheck must fail if:

* parser writes inventory/quests/abilities/XP directly
* parser scans command output
* parser scans Story Card text as canon
* parser omits safety flags
* parser treats player input as completed success

ReleaseCheck may warn if:

* parser shell is present but not fully active
* family detection is limited
* resolver/proposal/validator not active yet
