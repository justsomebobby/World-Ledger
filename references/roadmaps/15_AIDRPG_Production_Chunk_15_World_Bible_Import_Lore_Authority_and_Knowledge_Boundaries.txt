# AIDRPG Production Chunk 15 — World Bible Import, Lore Authority, and Knowledge Boundaries

## 0. Document status

**Document name:** AIDRPG Production Chunk 15 — World Bible Import, Lore Authority, and Knowledge Boundaries  
**Production sequence:** 15 of 25 remaining production chunks  
**Build target:** WorldLedger V0.17.14 threat/encounter-boundaries accepted build / AIDRPG Core MVP expansion path  
**Purpose:** Add world bible/lore import boundaries, source authority tiers, static-world-fact records, player-knowledge records, lore conflict handling, Story Card reference safety, context-lore safety, and discovery rules without letting lore text directly mutate gameplay state.  
**Status:** Core systems production chunk.  
**Follows:** Production Chunk 14 — Threat Benchmark, Encounter Logic, and World Scaling Boundaries.  
**This document does not contain final script code.**

Production Chunk 15 exists because AI Dungeon worlds need lore, but lore is dangerous if the script treats every card, memory, or context line as live state.

This chunk is where the system learns the difference between:

```text
world fact
story card reference
current scene truth
player-known truth
rumor
myth
quest hook
creature ecology reference
region danger note
historical lore
hidden lore
active gameplay event
```

Old and rough builds risked:

```text
Story Card says player owns item -> item appears in inventory
Story Card says player is in city -> location changes
World lore mentions dragon -> encounter spawns
World lore says vampires are immortal -> player death logic changes
Context says quest completed -> quest completes
Lore says empire hates player -> reputation changes
Card says player is level 10 -> progression changes
Hidden lore appears in context before discovery
Conflicting lore silently overwrites accepted facts
```

This chunk prevents those failures.

World Bible and Story Card material can guide context and classification.

It cannot directly create active player state, items, quests, actors, combat, XP, rewards, forms, or encounters unless a dedicated owner system validates an event through normal gameplay flow.

---

# 1. Chunk doctrine

```text
Lore is not live state.
World fact is not player knowledge.
Hidden lore is not known lore.
Story Card text is not gameplay mutation.
Context text is not gameplay mutation.
Rumor is not fact.
Myth is not proof.
History is not current scene.
Region danger is not an encounter.
Creature lore is not combat.
Lore authority guides validation; it does not bypass validation.
```

World lore should make the game richer, not corrupt the ledger.

---

# 2. Why this chunk comes now

Production Chunk 14 locked threat benchmarks and encounter boundaries.

World Bible import comes next because later chunks depend on reliable lore authority:

```text
region structure
faction facts
creature ecology
species/race lore
divine/cosmic rules
settlement names
historical facts
quest context
world-specific threat labels
knowledge gates
card/context budgeting
long-run memory stability
```

If lore authority is not safe before region/faction/creature chunks, those chunks will keep asking:

```text
Can this card be trusted?
Is this lore known to the player?
Did this lore spawn a live event?
Which source wins when lore conflicts?
```

Chunk 15 answers those questions.

# 7. Story Card lore boundary

AI Dungeon Story Cards are important, but unsafe as live-state mutation sources.

Default Story Card behavior:

```text
read as supporting lore/reference
never directly mutate player inventory
never directly mutate current location
never directly mutate active quest state
never directly mutate actor presence
never directly mutate body/race/form
never directly mutate XP/level/stats
never directly spawn encounter/combat
```

Allowed Story Card uses:

```text
support world lore
support region/faction/species/creature descriptions
support names/aliases/reference matching
support context summaries after knowledge-boundary filtering
support validator warnings about contradictions
support future card mirror dry-run output
```

Forbidden Story Card uses:

```text
Player owns Crown of Dawn -> inventory grant
Player is level 10 -> level set
Current location is Chapel -> teleport/location overwrite
Dragon attacks here -> encounter spawn
Mira trusts player -> relationship mutation
Player is dragon -> form/race mutation
Quest completed -> quest completion
```

# 8. Context lore boundary

Context is output to the AI model.

It must never be re-imported as fresh gameplay truth.

Rules:

```text
ContextBuilder text is non-canon source for mutation
context summaries can guide generation
context summaries cannot be parsed as new events
context must label hidden/rumor/candidate facts carefully
context must not leak hidden lore
```

Critical rule:

```text
Anything generated by /context, /status, /sheet, /lore, /world, /knowledge,
/debug, /releasecheck, or CardSync mirror output must be source-blocked from gameplay mutation.
```

# 9. Lore CanonValidator expansion

CanonValidator must enforce lore safety.

## 9.1 Accept lore claim when

```text
source is allowed for lore import
claim category is recognized
claim does not attempt active gameplay mutation
claim has authority tier assigned
operation key not duplicate
```

Result:

```text
LoreClaimRecord and possible WorldBibleRecord
no owner-system mutation
```

## 9.2 Accept player knowledge update when

```text
safe runtime event shows player discovered/read/heard/witnessed lore
knowledge target is bound
not command/context/card source unless card is an in-world object being read through gameplay output
operation key not duplicate
```

Result:

```text
PlayerKnowledgeRecord update
no unrelated gameplay mutation
```

## 9.3 Reject gameplay mutation from lore when

```text
Story Card says active state
context says active state
command output says active state
lore claim tries to grant item/XP/ability/form/quest/combat result
hidden lore tries to enter player-known context
rumor tries to become confirmed fact
```

# 11. Manager behavior

## 11.1 LoreImportManager

Should:

```text
create import session
normalize source records
extract lore claims conservatively
assign authority tier
assign visibility/player knowledge status
create WorldBibleRecords only for accepted lore claims
create conflict records when needed
block active gameplay mutation attempts
record operation keys
mark lore/context dirty
```

Must not:

```text
add items
complete quests
spawn actors
move current location
change player identity/form
award XP/levels/stats
start combat/encounters
change reputation/faction standing
```

## 11.2 LoreAuthorityManager

Should:

```text
rank sources by authority
resolve conflicts or mark unresolved
preserve runtime current state against lower-authority lore
separate world fact from player knowledge
separate public lore from hidden lore
expose warnings to /lore and /integrity
```

## 11.3 KnowledgeBoundaryManager

Should:

```text
filter lore before context insertion
exclude hidden lore unless revealed
label rumor/myth/candidate lore
prevent player-unknown facts from being written as player-known
prevent context summaries from becoming mutation sources
```

# 12. CardSyncLite integration boundary

This chunk does not activate generated card writes.

Allowed:

```text
read existing cards as possible lore references if source mode allows
record card source as supporting_story_card
quarantine/block active gameplay claims from cards
produce dry-run card audit/mirror notes
```

Forbidden:

```text
write new generated lore cards
rewrite protected cards from lore import
treat card prose as owner-state truth
sync card edits into gameplay state automatically
```

CardSync remains safe/dry-run unless later package activates protected writes with tests.

