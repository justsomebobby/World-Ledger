AIDRPG Build Chunk 3 — State Schema Lock

0. Document status

Document name: AIDRPG Build Chunk 3 — State Schema Lock
Build target: AIDRPG Core MVP v0.1
Purpose: Lock the exact state schema, bucket names, default values, ownership rules, and mutation boundaries before final script code is generated.
Status: Practical build document.
Follows: Build Chunk 2 — File and Module Layout Plan.
This document does not contain final script code.

This chunk exists because the script cannot be stable if each build step invents field names while coding.

The state schema must be locked before StateManager, commands, runtime hooks, validation, reducers, ContextBuilder, CardSync, migration, cleanup, or tests are coded.

⸻

1. Purpose of Build Chunk 3

Build Chunk 3 defines the canonical root state shape for AIDRPG Core MVP v0.1.

It answers:

* what state.aidrpg contains
* what every root bucket is named
* what every bucket owns
* what default values are used
* which module may mutate each bucket
* which modules may only read each bucket
* what must be preserved during repair/migration
* what must never be inferred from cards/context/commands
* what fields are MVP-active versus placeholder/deferred

The goal is to let the first real code build initialize state without guessing.

⸻

2. Core schema doctrine

AIDRPG uses one canonical state root:

state.aidrpg

All AIDRPG gameplay truth, runtime metadata, audits, migration records, card registry data, and feature flags live under that root.

No major system should create hidden sibling roots like:

state.tasis
state.playerData
state.cardSync
state.inventorySystem
state.patchData

If legacy roots are found later, migration may read/quarantine them, but new truth belongs under state.aidrpg.

⸻

3. Required root state buckets

The root state must contain exactly these primary buckets for Core MVP v0.1:

state.aidrpg = {
  meta,
  features,
  runtime,
  startup,
  player,
  body,
  progression,
  inventory,
  abilities,
  quests,
  actors,
  places,
  time,
  cards,
  operationLedger,
  audits,
  migration,
  quarantine,
  dirty,
  cleanup
}

Every bucket must exist after StateManager initialization.

If a bucket is missing, StateManager must create that bucket without erasing valid existing buckets.

⸻

4. Root state ownership map

Bucket	Primary Owner	May Read	Must Not Mutate
meta	StateManager	all modules	parser, cards, context
features	StateManager / ReleaseCheck	all modules	parser, cards, context
runtime	RuntimeHookContract	commands, audits	reducers except via hook metadata
startup	StateManager / Startup importer later	commands, releasecheck	parser after setup lock
player	StateManager / future PlayerReducer	commands, context, cards	cards, context, commands
body	BodyReducer	commands, context, cards	parser direct, cards, context
progression	ProgressionReducerLite	commands, context, cards	parser direct, cards, context
inventory	InventoryReducer	commands, context, cards	parser direct, cards, context
abilities	AbilityReducer	commands, context, cards	parser direct, cards, context
quests	QuestReducerLite	commands, context, cards	parser direct, cards, context
actors	ActorReducerLite	commands, context, cards	parser direct, cards, context
places	PlaceReducerLite	commands, context, cards	parser direct, cards, context
time	TimeReducerLite	commands, context, cards	parser direct, cards, context
cards	CardSyncLite	commands, releasecheck	parser, context
operationLedger	OperationLedger	validators, reducers, audits	parser direct, cards, context
audits	AuditLogger	commands, releasecheck	parser as gameplay
migration	StateManager / Migration	commands, releasecheck	cards as canon
quarantine	Migration / StateManager	commands, releasecheck	cleanup as auto-resolver
dirty	DirtyQueue helpers / reducers	CardSync, ContextBuilder	dirty target as gameplay truth
cleanup	CleanupManagerLite	commands, releasecheck	cleanup creating truth

5. Schema version policy

5.1 Required fields

The schema must include:

meta.schemaVersion
meta.buildName
meta.buildStage
meta.projectName

5.2 MVP value

For Core MVP v0.1:

schemaVersion = 1
buildName = 'AIDRPG Core MVP v0.1'
buildStage = 'core_mvp_v0_1_foundation'
projectName = 'AIDRPG'

5.3 Version mutation rule

Only StateManager or explicit future migration may update schemaVersion.

No gameplay event may update schemaVersion.

10.5 Mutation rule

Allowed mutation paths:

* startup import before lock
* validated transformation event later
* validated title grant later
* validated aging/time skip later
* explicit manual override later
* safe structured migration

Forbidden mutation paths:

* Story Card text
* Context text
* command output
* dream/vision
* disguise
* NPC introduction
* vague metaphor

27. State repair policy

StateManager may repair:

* missing root state
* missing buckets
* missing default fields
* invalid enum values, using safe fallback and warning
* malformed arrays, replacing with empty arrays only if no valid data exists
* resource current/max bounds, with warning
* cap oversized audit arrays

StateManager must not:

* erase valid records
* import Story Card prose as truth
* create gameplay outcomes from old logs
* enable generated cards
* resolve quarantine automatically
* delete active inventory/quests/actors/abilities

28. State mutation source policy

28.1 Allowed gameplay mutation path

The normal gameplay mutation path is:

AI output -> ParserHit -> EventProposal -> CanonValidator -> ReducerRegistry -> OwnerReducer -> OperationLedger -> DirtyTargets -> Audit

28.2 Non-gameplay mutation path

Allowed structural mutations:

StateManager initialization
StateManager repair
migration/quarantine structural repair
audit writes
runtime hook metadata
command suppression metadata
cleanup of temporary/audit records

28.3 Forbidden mutation sources

Forbidden as gameplay sources:

* Story Card text
* Context text
* command output
* debug output
* help text
* old logs
* archived summaries
* generated cards
* protected cards
