# AIDRPG Production Chunk 05 — Inventory, Equipment, Scene Items, and Custody Depth

## Document status

Production sequence: 05 of 25.
Build target: WorldLedger V0.17.4 body/identity accepted build.
Purpose: Deepen inventory, equipment, scene-item, custody, item-history, and currency safety without false item grants or unsafe economy activation.

## Doctrine

```text
Visible is not owned.
Available is not acquired.
Offered is not received.
Promised is not paid.
NPC custody is not player custody.
Dropped is not deleted.
Consumed is not carried.
Destroyed is not usable.
Dreamed is not owned.
Quoted is not owned.
Denied is not acquired.
Failed grab is not acquisition.
```

Inventory truth must be conservative, durable, and auditable.

## Inventory state model

Preferred shape:

```text
inventory: {
  items: {},
  equipped: {},
  stored: {},
  sceneItems: {},
  custody: {},
  currency: {},
  itemHistory: [],
  warnings: [],
  notes: []
}
```

Arrays are acceptable if already used, but stable item keys are required.

## ItemRecord schema

```text
ItemRecord {
  id,
  key,
  displayName,
  normalizedName,
  quantity,
  category,
  tags,
  stackable,
  unique,
  durability,
  accessState,
  owner,
  holder,
  custodyKey,
  locationKey,
  equippedSlot,
  sourceOperationKey,
  sourceEventId,
  createdTurn,
  updatedTurn,
  historyKeys,
  warnings,
  notes
}
```

Keys are stable and family-scoped. They must not contain full raw output, quotes, dreams, command text, or card/context prose.

Quantity must be positive for active records. Negative quantity quarantines or repairs safely without granting new items. Unique items do not stack unless policy says so.

## AccessState model

```text
owned carried equipped stored visible available_loot offered npc_custody place_custody inaccessible lost consumed destroyed unknown
```

Owned/carried/equipped/stored are player access states.

Visible/available/offered are not owned.

NPC/place custody and inaccessible are not player-owned.

Lost/consumed/destroyed are not usable.

Unknown is not owned by default.

## Equipment shell

Equipment is a view/state of inventory, not a separate truth source.

Slots:

```text
mainHand offHand head body hands feet ring1 ring2 neck back customSlots
```

Equipped item must exist as owned/carried/equipped. Equipping requires accepted equip event or safe startup source. Equipment stat modifiers are deferred. Body/form equipment constraints are warnings/context labels only in this chunk.

## Currency model

Currency must be explicit and duplicate-safe. Acceptable simple shape:

```text
currency: { gold: 0, silver: 0, copper: 0, custom: {} }
```

or record shape with amount/source keys.

Rules:

```text
promised reward does not increase currency
ready reward does not increase currency
paid reward may increase currency only once
buy/sell/spend is deferred until economy mini-spec
```

## Categories/tags

Categories:

```text

```

Tags are descriptive only. Magical does not grant ability. Quest item does not complete quest. Material does not enable crafting yet.

## ItemNameSanitizer depth

Must handle:

```text
the rusted iron key, but the goblin snatches it away -> rusted iron key
red healing potion from Mira -> red healing potion
three silver arrows on the table -> silver arrows + quantity 3 if supported
jeweled crown that Mira refuses to give you -> jeweled crown
idea of a brass key -> brass key with abstract/metaphorical flag
```

Preserve meaningful modifiers: rusted, iron, red healing, jeweled, silver, old wooden, masterwork, cracked, black gate, cellar.

## Inventory CanonValidator expansion

Accept owned acquisition only when safe output/startup source confirms actual acquisition/handoff/receipt/pickup, target is bound, no denial/failure/revocation/hypothetical/quote/dream/abstract/visible/available/offered/custody/attempt-only flag, and operation key is not duplicate.

Reject ownership when any unsafe flag is present:

```text
deniedByLocalClause failedOrRevoked abstractOrMetaphorical quotedSpeech dreamOrVision visibleOnly availableOnly offeredOnly futureIntent attemptOnly command/context/card/audit/debug source
```

Use pending/scene item/custody for:

```text
You see a silver ring on the table.
The goblin drops a rusty dagger.
Mara offers you the key.
The chest contains a potion.
The jeweled crown rests behind glass.
```

## Mixed clause rule

```text
Mira refuses to give you the jeweled crown, but she hands you the red healing potion.
```

Expected:

```text
jeweled crown not owned
red healing potion acquired once if otherwise safe
```

Do not apply the handoff verb to the denied item or the denial to the accepted potion.

## InventoryReducer behavior

Acquisition/handoff commit:

```text
1. Confirm accepted validation result.
2. Confirm safe source and no unsafe routed flags.
3. Confirm item target key/displayName.
4. Check operation key.
5. If duplicate, skipped_duplicate.
6. Add or merge item by stack/unique policy.
7. Set accessState carried/owned unless equip/stored validated.
8. Set owner/holder player.
9. Add item history.
10. Add operation key.
11. Mark dirty targets.
12. Audit.
```

Scene items update sceneItems and never inventory.items.

Custody updates custody records and never owned items unless player holder confirmed.

Consume/drop/lose/destroy update accessState/history rather than deleting immediately.

Equip/unequip shell requires item already owned/carried and accepted equip event. No stat bonuses.

## Currency and reward payment split

Preferred split-owner policy:

```text
QuestReducer handles reward status.
InventoryReducer handles currency changes.
```

Reward promise does not pay. Reward ready does not pay. Payment creates currency once. Repeated output skips. `/quests` display cannot pay.

## Pass / warn / fail

PASS if access states are separated, false grants rejected, mixed clauses split, scene/custody items not owned, currency promise/payment separated, duplicates prevented, InventoryReducer rejects unsafe data, display is honest, command/context/card item text non-canon, cleanup preserves active/durable data, tests pass.

WARN if equipment shell is display-only, category/tags are display-only, currency is simple but duplicate-safe, economy/crafting remain disabled, non-humanoid equipment constraints are deferred.

FAIL if visible/offered/available becomes owned, failed/denied/dream/quote/abstract becomes owned, custody item becomes player-owned, reward promise pays currency, reward duplicates, command/context/card creates item/currency, negative quantity becomes grant, cleanup deletes active item/durable reward key, buy/sell/craft mutates, or InventoryReducer trusts unsafe data.

## Final doctrine

```text
An item mention is not inventory.
A visible item is not inventory.
A promised reward is not currency.
A custody item is not owned.
A failed acquisition is not acquisition.
Only accepted, validated, duplicate-safe inventory events change player inventory.
```
